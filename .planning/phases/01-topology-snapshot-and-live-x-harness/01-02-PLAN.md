<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| X server → `FScreenRefreshTopology()` | Synchronous X replies and Atom names cross into authoritative process memory. |
| Committed snapshot → legacy monitor consumers | New immutable facts must reconcile without a window where consumers see mismatched state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering / Denial of Service | XRR reply adapter | high | mitigate | Initialize count to `-1`, validate/copy every field through Plan 01, release X ownership exactly once, and retain last-good state on any failure. |
| T-01-05 | Tampering | publication/reconciliation boundary | high | mitigate | Stage every fallible legacy allocation before one snapshot swap, then apply a no-fail synchronous reconciliation before downstream callbacks. |
| T-01-06 | Denial of Service | runtime query failure | medium | mitigate | Return explicit failure, emit bounded diagnostics, preserve pointer/epoch/view, and wait for a later dirty generation rather than looping. |
</threat_model>
