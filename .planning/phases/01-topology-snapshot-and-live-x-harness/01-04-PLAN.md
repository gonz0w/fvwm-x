<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| X event queue → core event loop | An external X client/server can generate a sustained stream of topology-related notifications. |
| Refresh result → downstream work | Only a validated semantic commit may trigger expensive EWMH, module, pan-frame, and Status effects. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-10 | Denial of Service | topology event storm | high | mitigate | Constant-time marking, one armed generation, 50 ms quiet period, 250 ms cap, top-of-loop due check, and existing X event budget. |
| T-01-11 | Denial of Service | `My_XNextEvent()` timeout merge | medium | mitigate | Select the minimum valid timeout with ceiling arithmetic and preserve force-poll/zero-time guards to prevent spin or starvation. |
| T-01-12 | Tampering | downstream commit dispatch | high | mitigate | Switch on explicit FScreen result; only `CHANGED` invokes each named downstream helper once after completed reconciliation. |
</threat_model>
