## Service and ownership

Use the existing browser executable with one separate `--job-worker` child and
private bounded JSON pipes. Enumeration's ten-second timeout and navigation
supersession remain independent. One mutation job may be active; zero are queued.
Navigation does not silently cancel it. Closing the owner, losing transport or
restarting the WM requests cancellation and retains the child slot until reap.
Unexpected worker loss reports interrupted/unknown remaining effects and is not
a reason to replay a mutation.

The backend owns `internal/filejobs` and the private streaming worker. The browser
owns native presentation, generation-checked admission, a bounded progress mailbox,
reliable decision/item/final delivery, control writes and process lifetime. Reuse
existing provider correlation and typed action machinery; introduce no daemon,
network listener, database, bus or parallel core state authority.

The frozen private request/event/control types live in
[types.go](../../bin/FvwmPrompt/internal/filejobs/types.go). Requests carry schema,
request ID, browser job generation, operation, observed snapshot/selected IDs and
literal byte names/destination paths. A name is required for mkdir/rename and
may override the destination basename for one copy/move/link target; it is refused
with multiple targets and unused for trash/restore/delete. Operations are mkdir,
rename, copy, move,
link, trash, restore and delete. Delete requires explicit permanent intent and a
separate native confirmation. Events distinguish progress, one pending decision,
per-target outcomes and final state; source remaining, destination present, complete
content and complete promised metadata are separate observations. Destination
present means output made by this job, not an unrelated conflicting object.

Limits: 256 top-level targets, 4,096 traversal entries, depth 64, 64-KiB copy chunks,
at most ten progress updates/second, 32-KiB control/event records and one pending
decision expiring after 60 seconds, at most 4,096 control records and a 30-minute
worker context deadline checked between steps. It cannot preempt a blocking OS
call. The initial request is bounded by the existing
file-model wire limit. Unknown recursive totals remain unknown; cancellation is
best effort, with already completed effects and partial cleanup reported explicitly.

## Filesystem contract

Open and retain source/destination directory handles, compare observed identities
and generations before mutation, and use opened-file identities before copying
content. Existing pathname-based launch validation is insufficient for jobs.
Confinement is relative to admitted directory roots; opening `/` is not a useful
confinement boundary. Root APIs can follow contained symlinks and do not freeze
entries. Rechecking before unlink cannot provide atomic compare-and-unlink against
a hostile concurrent same-user writer; no such guarantee is claimed.

No existing destination is overwritten. Conflicts allow Skip, New name or Cancel.
Exclusive creation/publication protects a competing destination. Where a portable
safe no-replace directory rename is unavailable, exclusive destination creation
and bounded copy/remove provide explicitly non-atomic behavior. Cross-filesystem
move removes source content only after complete content and required metadata;
failed source removal reports a complete destination plus retained source/partial
outcome. A partial same-filesystem fast move may leave both names sharing an
inode; it is not an independent copy or rollback. Failed copying never becomes source removal.

Copy regular files and directories; reproduce symbolic links as links without
traversing their targets. Link creates a symbolic link containing literal source
bytes. Refuse devices, sockets and FIFOs. Preserve ordinary permission bits and
modification times where promised; do not copy set-ID privileges. Ownership, ACLs,
extended attributes, birth time, sparse allocation and hard-link topology are not
part of this metadata contract. Preserve invalid-UTF-8 filenames independently of
sanitized display labels; never derive commands from filenames.

Adopt the home-trash storage subset of the
[Freedesktop Trash 1.0 specification](https://specifications.freedesktop.org/trash/1.0/).
Resolve its location from the worker's inherited XDG environment, not a request.
Require a private owned area and reserve names exclusively. Publish recoverable
metadata only for complete content; incomplete staging and duplicate source/trash
copies after failure remain explicit partial outcomes. Restore validates the
entry and its metadata and refuses missing original parents or conflicts.
Unsupported filesystem/private-area capabilities refuse trash; never fall back to
permanent deletion. This is not a claim of every mount-trash facility or undo.

## Verification boundary

The supported compiler remains the existing patched baseline in
[go_version.py](../../tools/maintenance/go_version.py); API presence in an older
compiler is not qualification. Run focused development tests and early affected
platform checks, then one combined six-target filesystem and Linux actual-X/theme
checkpoint. Exercise conflict preservation, stale/replaced targets, links, recursive
limits, cross-filesystem behavior, full/read-only/permission/interruption cases,
cancellation, malformed/lost workers and native owner destruction/restart.
Capture meaningful editor/decision/progress/outcome views in Slate, Dune and
Classic enlarged configurations. Qualify actual received states and child waits;
do not infer rollback, native CPU or full release acceptance from component tests.
Missing required evidence leaves #68 open. No performance comparison is due after
PR288's new measured reference, and no full unrelated install/WM matrix follows
from each operation.
