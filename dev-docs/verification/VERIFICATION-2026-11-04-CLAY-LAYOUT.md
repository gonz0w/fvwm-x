## Delivered source boundary

Four related stories pin unchanged optional Clay source/license; add a bounded
arena/independent row solver; validate copied geometry before existing atomic
publication and native fallback; and extend the existing drawing comparison
fixture with explicit native/Clay layout variants and committed/fallback witnesses.
The default-disabled `layout-eval` feature creates non-installed private targets.
Ordinary targets retain direct `ui_layout_row` and a no-op metadata hook. The core,
Form and ordinary/shared install dependency owners acquire no Clay requirement.
The source distribution does grow: the unchanged header is 303,701 bytes and its
license is 891 bytes, plus provenance, adapter, glue and tests. No production code
is removed; the small existing integer policy remains the simpler baseline.

Equal positive spans and uncompressed content can enter the Clay experiment.
Its smallest-first equalization differs from native minimum-plus-weighted-surplus;
matching semantic actions/draw-hit rectangles is separate from identical widths.
Weighted spans, compression, explicit refusal and invalid input/output use native
policy. Existing Flocale measurement, icons, focus, updates, draw/hit geometry,
root frame/padding and configured legacy grid retain their owners. No Clay text,
input, scrolling, transitions or rendering is adopted. Pure output validation
checks finite bounds, identities, height, adjacency and complete integer coverage
before publication; arena-backed result pointers never escape the operation.

## Executed focused checks and retained failures

Source review found an update false-positive: lifetime call counts could qualify
an ignored title update even when Clay kept equalized widths. The correction
stages a bounded metadata test tag from current title/active/pressed inputs and
commits it only after successful reflow. The fixture requires the exact known
updated tag; many startup or resize calls with old metadata cannot qualify.

The first offline host regression retained five passes and one failed fixed
vector. No VM/container was started by that attempt. The specified seven bytes
`1,0,0,0,0,0,0` independently produce FNV-1a32 value 299179820; the authored
escaped-literal constant was wrong. The one-constant correction was separately
checked. All six focused Python tests then passed in 0.001 seconds (0.075 seconds
including process/import), with the owned process group absent. This was native
macOS host Python 3.14.7 offline execution of the two-file JSONL/tag import scope,
not C, X11, native Linux/BSD GUI, sanitizer or release qualification.

The reviewed native Linux ARM64 GCC 13.3.0 profile reused PNG/SVG/session D-Bus,
NLS/docs off. Its first enabled configuration passed and ordinary plus two private
graphics Buttons controls linked. The six-target compile then failed in the new
private driver: the existing module header declared `buttons_layout_count` and
macro `byte`, colliding with new private names. All groups retired and the lab
stopped. That first compile remains failed; it is not rewritten as a passing run.

The recorded G4-C1 replan changed only the demonstrated private helper/local names
and consumed the bounded `write` result. A separately reviewed source17-to18
single-overlay plan reused the already linked controls and original G3 references;
it compiled only the two unfinished layout modules and their C oracle. All three
passed in 1.285 seconds; preparation/inspection took 1.604 seconds and dispatch
2.975 seconds. Seventeen guest commands passed with owned groups absent. The
complete prepared source has 2,505 pins; the original 17 overlays and later driver
repair are bound separately. Seven unchanged ELFs, original G3 controls and the
three owned partial-build control identities were checked before/after as scoped.
No old-binary identity is invented for the partial source17 controls.

The final container and machine shutdowns are confirmed. No C test binary, module,
UI case, screenshot, install, package update, resource configuration or full matrix
was executed by these plans. Existing Buttons fallthrough warnings remain; the
initial pinned Clay compilation also reports unused variables and one partial
initializer. These are retained rather than hidden or described as warning-free.
