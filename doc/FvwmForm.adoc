== NAME

FvwmForm - input form module for Fvwm

== SYNOPSIS

*Module FvwmForm* [ _Alias_ ]

FvwmForm must be spawned by Fvwm. If invoked from the command line,
FvwmForm prints its version number and exits.

== DESCRIPTION

FvwmForm provides a mechanism to get user input and act accordingly.
This is achieved by means of a form that the user can fill out, and from
which the user can select actions he wants Fvwm to take. A form consists
of five types of items: text labels, single-line text inputs,
mutually-exclusive selections, multiple-choice selections, and action
buttons. These items are arranged into several lines, with a very
flexible layout.

A text label only serves the purpose of explanation. It cannot accept
any input.

A timeout entry provides a mechanism for timing out the form and
performing a certain action when the timeout occurs. The countdown is
displayed similar to a text label except that it updates with the amount
of time left.

A text input field can be used to edit a single-line string. FvwmForm
accepts Emacs-style cursor movement keys. See FvwmFormInput for details.
Mouse copy is not supported, but you can paste.

A selection consists of several choices.

The selection itself is a logical entity that doesn't have any display
feature.

Each choice is displayed as a push-button followed by a explanatory text
label. When selected, an exclusive choice shows a circle in the middle,
while a multiple choice shows a check.

An action button, when activated sends one or more commands to Fvwm or
executes shell commands. The shell commands can contain the content of
the input fields on the form and reflect the setting of choices on the
form.

The action buttons can be activated thru keyboard or mouse.

== INITIALIZATION

FvwmForm invoked without an alias uses configuration commands starting
with "*FvwmForm".

Normally you would invoke FvwmForm with an alias representing the name
of a form, its configuration commands and configuration file. For
example, the command "Module FvwmForm Rlogin" uses configuration
commands starting with "*Rlogin", and reads the optional configuration
file "Rlogin".

All forms, regardless of alias, scan first for configuration commands
that start with "*FvwmFormDefault". These commands normally come from
the builtin form "FvwmForm-Form" which saves commands to the file
".FvwmForm".

The physical reading of the optional input file, ".FvwmForm", is done
only the first time FvwmForm is invoked, or after "FvwmForm-Form"
updates the file.

When the file ".FvwmForm" is read, it is done by sending the command
"Read .FvwmForm Quiet" to fvwm. Because of the way the "read" command
works, the file can reside in your personal fvwm user directory, or be
in the fvwm data directory. See the description of the read command in
the fvwm man page for more information about the environment variable
$FVWM_USERDIR.

Then FvwmForm reads the rest of the configuration fvwm has stored up.
Fvwm stores configuration on an ongoing basis. The initial configuration
comes from the .fvwm2rc file. Other sources, including "Read" commands
can define a form.

When letting FvwmForm and fvwm read files, remember that these files
contain commands that can execute shell commands, so you should be
careful about setting permissions on these files.

When FvwmForm is invoked with a window context, e.g. from a window menu,
all commands it sends to Fvwm will have that window context. This would
allow FvwmForm to control the window it is invoked from.

After all the configuration commands have been read, FvwmForm displays
the form defined by the commands.

== DEFAULTS

FvwmForm creates a built-in form named "FvwmForm-Form" that creates a
file called ".FvwmForm". This file contains saved default form colors
and fonts. Other forms use these defaults unless they are overridden
within the form.

The default creating form would normally be invoked from a "module
menu". For example, if you call your module menu "Module-Popup", you
would add the line: AddToMenu "Module-Popup" "FvwmForm Defaults"
FvwmForm FvwmForm-Form

When you select "FvwmForm Defaults" from your module menu, a form is
displayed that shows the current defaults and allows you to change them.
If you activate the "Save Restart Me" button, the ".FvwmForm" file is
written and "FvwmForm-Form" exits and restarts to show the new defaults.

An example of what this file might contain after a save is:

....
# This file last created by FvwmForm-Form on Sun Nov 28 11:18:26 EST 1999.
*FvwmFormDefault: Font 10x20
*FvwmFormDefault: InputFont 8x13bold
*FvwmFormDefault: ButtonFont 10x20
*FvwmFormDefault: TimeoutFont 10x20
*FvwmFormDefault: Fore white
*FvwmFormDefault: Back cornflowerblue
*FvwmFormDefault: Colorset -1
*FvwmFormDefault: ItemFore green
*FvwmFormDefault: ItemBack gray40
*FvwmFormDefault: ItemColorset -1
*FvwmFormDefault: ButtonPointer hand2
*FvwmFormDefault: ButtonInPointer star
*FvwmFormDefault: InputPointer gumby
*FvwmFormDefault: ButtonPointerFore blue
*FvwmFormDefault: ButtonPointerBack gray
*FvwmFormDefault: ButtonInPointerFore gray
*FvwmFormDefault: ButtonInPointerBack blue
*FvwmFormDefault: InputPointerFore
*FvwmFormDefault: InputPointerBack
....

The commands in this file are just like any other FvwmForm command
except that they start with "*FvwmFormDefault".

FvwmForm only reads the file ".FvwmForm" the first time it is started or
after the file is changed by "FvwmForm-Form". It does so by sending the
command "*FvwmFormDefault: Read x". With "x" set to "y" or "n". "n"
makes FvwmForm send a "read .FvwmForm quiet" command to fvwm.

== VARIABLE SUBSTITUTION

If you supply variables and values on the command line used to start
FvwmForm (like this):

Module FvwmForm MyForm ACTION=Browse "TITLE=Browse Form"

Then all FvwmForm input commands undergo variable substitution. The
variables from the command line are exported. Then every command gets
expanded using the variables from the environment. For example, assuming
the above invocation of "MyForm", commands would be changed like this:

Before *MyForm: Text "$TITLE, Home $HOME, Going to $ACTION" After
*MyForm: TEXT "Browse Form, Home /home/me, Going to Browse"

Using this facility should make it possible for one form to be used for
different sets of input data.

== CONFIGURATION

The following commands can be set in the .fvwm2rc file or thru any of
the other ways that fvwm can accept commands. The simplest technique is
to create a file in the read-only architecture-independent data
directory, [PREFIX/share/fvwm] or your personal fvwm directory
[$HOME/.fvwm], that matches the form alias.

In the following paragraphs the string "FvwmForm" would normally be the
form alias.

FvwmForm reads commands before the form is ever displayed, and while the
form is being displayed.

The following commands are accepted before the form is displayed:

 Back
 Button
 ButtonFont
 ButtonInPointer
 ButtonInPointerFore
 ButtonInPointerBack
 ButtonPointer
 ButtonPointerFore
 ButtonPointerBack
 Choice
 CloseCommand
 Command
 CommandAppend
 Colorset
 Font
 Fore
 GrabServer
 Input
 InputAppend
 InputFont
 InputHex
 InputPointer
 ItemBack
 ItemColorset
 ItemFore
 InputPointerFore
 InputPointerBack
 Line
 Message
 PadVText
 Position
 Selection
 Separator
 Text
 TextHex
 Timeout
 TimeoutFont
 Title
 UIScale
 UseData
 WarpPointer

The following commands are accepted while the form is displayed:

 Map
 Stop
 UnMap

The "Map", "UnMap" and "Stop" facility is under development and is
currently not explained in this document, since it is likely to change.

The order of the options DOES matter. The first background text color,
"*FvwmFormBack", encountered before a displayable item sets the default
background color for the entire form.

Other than that, colors, fonts, text, choices and buttons can be
intermixed in any order. The are no builtin limits on form size, number
of items on a form, or number of fonts or colors used.

**FvwmForm: GrabServer*::
  This option makes FvwmForm grab the mouse pointer on startup. This
  feature is useful for things like logout verification.

**FvwmForm: WarpPointer*::
  This option makes FvwmForm warp the mouse pointer into its window on
  startup. It saves the user some mouse-travelling.

**FvwmForm: Geometry ``_geometry_``*::
  Specifies the FvwmForm window location. This is similar to what the
  Position option does but is more flexible.

**FvwmForm: Position ``_x_ _y_``*::
  Puts the FvwmForm window at location (_x_, _y_) on the screen. By
  convention, a negative _x_ (_y_) value measures distance from the
  right (bottom) of the screen.
+
If this option is omitted, FvwmForm starts at the center of the screen.

**FvwmForm: UIScale monitor | off*::
  Startup-only policy for the Form's own UI. The default is off, preserving
  existing geometry and fonts at 1x. Put `UIScale monitor` before the controls
  to follow the core's effective monitor scale, including fractional factors.
  The monitor is chosen from the Form's actual root-pixel window rectangle
  using the shared ownership policy. Client pixels, module packet geometry
  and the actual parent window size are not multiplied by the scale factor.
+
This bounded opt-in requires one List on its own Line with ListViewport.
Supported items are Text/TextHex, fixed-width Label, Input/InputHex, Button,
List and Timeout. The timeout's remaining ticks and renewal cadence are
preserved, including an empty countdown label used only for idle close.
Forms containing selection/choice controls, Message fields, Separator items,
swallowing or multiple Lists keep the complete 1x view and report a diagnostic.
Existing personal Forms remain unchanged unless they opt in.
+
The module prepares fonts and geometry from retained logical metrics before
publishing an in-place reflow. It retains the Form and child windows, input
drafts and active control, collection focus, selection/range anchor and
viewport anchor. A focused entry intentionally scrolled offscreen is not
revealed. Resizing and scale changes leave the native collection generation
unchanged; ListLayout still uses its separate publication handshake.
+
If the actual window cannot contain the prepared minimum, the module requests
the required absolute window size and retains its previous complete view
until an actual resize provides enough space. Minimum-size hints alone do
not establish a resize. A pending list snapshot defers scale publication until
ListCommit or ListAbort. Failed preparation retains the preceding resources
and view. Missing initial monitor metadata retains the 1x fallback; incomplete
or malformed metadata does not replace an accepted monitor snapshot.
+
Actual returned font metrics determine layout. A fixed bitmap font alias may
keep its native glyph size while UI spacing grows. Use scalable fonts when
fractional glyph sizing is needed; this option does not guarantee that every
configured alias has a scalable font variant.

**FvwmForm: Colorset ``_n_``*::
  Tells the module to use colorset _n_.

**FvwmForm: Back ``_color_``*::
  Specifies the background color of the FvwmForm window and any text in
  the window. The first background color FvwmForm reads determines the
  overall screen background color. Switches off the Colorset option. See
  DEFAULTS.

**FvwmForm: Fore ``_color_``*::
  Specifies the foreground color for displaying text labels. Switches
  off the Colorset option. See DEFAULTS.

**FvwmForm: ItemColorset ``_n_``*::
  Tells the module to use colorset _n_ for items.

**FvwmForm: ItemBack ``_color_``*::
  Specifies the background color for the text input windows, and the
  buttons. Buttons are displayed as 3D depressable buttons. Inputs are
  displayed as 3D indented fields. Medium shade background colors work
  best. Switches off the ItemColorset option. See DEFAULTS.

**FvwmForm: ItemFore ``_color_``*::
  Specifies the foreground color for the text input strings and button
  text. Switches off the ItemColorset option. See DEFAULTS.

**FvwmForm: Font ``_font_``*::
  Specifies the font for displaying plain text. See DEFAULTS.

**FvwmForm: ButtonFont ``_font_``*::
  Specifies the font for text in the action buttons. See DEFAULTS.

**FvwmForm: InputFont ``_font_``*::
  Specifies the font for text input. See DEFAULTS.

**FvwmForm: TimeoutFont ``_font_``*::
  Specifies the font for display the timeout counter and related text.
  See DEFAULTS.

**FvwmForm: Line ``_justification_``*::
  Starts a new line. A line can contain any number of text, input,
  buttons and choice items. A FvwmForm window can have any number of
  lines. The width of the window is that of the longest line.
+
Justification of items in the line is specified by _justification_,
which can be one of the following:
+
*``_left_``*:::
  Items are justified to the left of the window.
*``_right_``*:::
  Items are justified to the right of the window.
*``_center_``*:::
  Items are placed in the center of the window.
*``_expand_``*:::
  If there is only one item in the line, the item is centered in the
  window. If two or more items are present, they are spread to fill the
  whole width of the window.

**FvwmForm: Message*::
  Defines a text area on the form that contains the last error message
  from fvwm. For purposes of determining form size, the message area is
  considered to be 80 bytes long. Its actual length is the same as the
  message received. If the message exceeds 80 bytes, you can see the
  rest of the message by resizing the form.
+
You should not attempt to put any text, buttons or input fields on the
same line after a message field. Messages greater than 80 bytes will
overlay the remainder of the line.

**FvwmForm: PadVText ``_Pixels_``*::
  The number of pixels used as vertical padding between text items, line
  to line. The default is 6 which looks good on lines containing text
  intermixed with input boxes, choices or buttons.
+
For straight text, such as might appear on a help form, padding of zero
looks better.
+
(There are lots of other padding values used in form layout which can't
currently be changed with commands.)

**FvwmForm: Text ``_string_``*::
  Displays _string_ as plain text. Line breaks must be achieved by
  multiple *FvwmForm: Line and *FvwmForm: Text options. Blanks may be
  used to provide extra padding between items.

**FvwmForm: TextHex ``_xhexbytes_``*::
  Display literal text encoded as an `x` prefix followed by hexadecimal byte
  pairs. `x` alone displays empty text. Both uppercase and lowercase hex digits
  are accepted. At most 1000 decoded bytes are allowed; the complete directive
  must also fit FVWM's module configuration record limit. Malformed hex,
  invalid UTF-8, NUL and C0/C1 control characters are refused before an item
  is added. Use multiple Line/TextHex directives for separate lines.
+
Decoding preserves spaces, quotes, backslashes, percent signs, dollar signs
and other admitted UTF-8 text exactly. The decoded text is data: FvwmForm does
not evaluate field substitutions or interpret quoted-string escapes in it.
For example, `TextHex x24286669656c64292025` displays `$(field) %` literally.

**FvwmForm: Label ``_name_ _width_ _string_``*::
  Create a named, fixed-size text area using Font and text colors. Name is
  1..64 ASCII letters/digits, hyphen or underscore; keep names unique. Width is
  1..4096 font units, checked against X geometry. The complete quoted text has
  at most 1024 source bytes. Text is clipped to its fixed rectangle; later
  updates neither resize the Form nor create another X child.

**FvwmForm: LabelViewport ``_name_``*::
  Opt a previously declared named Label into available parent width. The Label
  must be alone on its Line, and the Form must have one ListViewport. Its
  configured width remains the minimum; resizing can expand and shrink the
  current width. When text overflows, the actual font measures a complete-character
  prefix followed by `...`. The original value remains available for later
  resizing or replacement. Ordinary Labels retain fixed clipping, including at
  1x. For example:
+
----
*MyForm: Line left
*MyForm: Label status 40 "Ready"
*MyForm: LabelViewport status
*MyForm: Line left
*MyForm: List items 40 8
*MyForm: ListViewport 18 1
----
+
  If font preparation fails during scaling, the previous complete view remains;
  bitmap aliases can retain their native glyph size. Scalable fonts provide
  fractional text sizing.

**FvwmForm: SetLabel ``_name_ _string_``*::
  Replace a running Label's quoted presentation text, using the same text bound.
  Send `SendToModule MyForm SetLabel status "Folder refreshed"` to its exact
  alias. The old text rectangle is cleared before painting the new value,
  clipped or fitted according to the Label configuration. Unknown/ambiguous names, plain Text items and malformed values refuse
  without changing the label. Label owns its name/value until replacement/exit.
  This is nonsensitive metadata, not a private-content delivery channel.

**FvwmForm: Title ``_string_``*::
  Displays _string_ as the window's title. The string must be enclosed
  in double quotes. Using this command with anything other than a string
  enclosed in quotes creates a blank title. If this command is not used,
  the window title is the form alias.

**FvwmForm: InputHex ``_name_ _size_ _xhexbytes_``*::
  Create an Input with a literal initial value using the same hex encoding,
  1000 decoded-byte limit and validation as TextHex. The size and geometry
  rules are the same as Input. `InputHex filter 40 x` creates an empty field;
  `InputHex filter 40 x61202262225c` initializes it to `a "b"\` exactly.
  The decoded value is not processed as a quoted string or executable command.
  Restart restores that exact initial value. Invalid input adds no field.

**FvwmForm: Input ``_name_ _size_ _init_string_``*::
  Specifies a text input item with name _name_. A sub window of _size_
  characters in width is used for editing. If _init_string_ is present,
  it is the initial string when FvwmForm starts or resets itself. The
  default initial string is "".
+
The size must be a positive integer.
The input dimensions must fit the X11 size range, from 1 to 65535 pixels.
An invalid Input line does not add a field.
Later valid Input lines remain usable.
+
You can mouse paste into an input field using button 2. Buttons 1 and 3
move the cursor in an input field. Pasting reads a complete STRING/8 cut
buffer of at most 64 KiB. Missing, malformed, or oversized buffers leave
all input fields unchanged.
+
Input fields are always in insert mode, overtyping is not supported.
+
Emacs type keystrokes are supported.
+
Control-a, Home and Begin move to the front of an input field. Control-e
and End move to the end of an input field. Control-b and Left move left
in an input field. Control-f and Right move right in an input field.
Control-p, Up, and Shift-Tab move to a previous input field if any, if
the form has one input field, recall previous value. Control-n, Down,
Return, Line-feed and Tab move to the next input field if any, if the
form has one input field, for control-n and Down, restore previous input
value. Control-h moves backward in an input field erasing a character.
Control-d and Delete delete the next character in an input field.
Control-k erases from the cursor to the end of an input field. Control-u
erases the entire input field.
+
When a restart button runs, each nonempty changed input value is saved in
that field's history. Each field can store 50 values. The fields then
return to their initial values. Clear, truncate and recall leave the field
ready for further input.
+
Meta(Mod1)-"<" retrieves the previous value of an input field.
Meta(Mod1)-">" retrieves the next value of an input field.
+
(For forms with one input field, use the much easier arrow keys.)

**FvwmForm: List ``_name_ _width_ _rows_``*::
  Create one native scrollable multiple-selection list. Width is 1..4096 font
  units (checked against X geometry); rows is 1..32. List uses ButtonFont and
  item colors. Subsequent ListItem directives append to this list. At most
  4096 rows and 256 selected rows are admitted; an invalid/over-limit item
  refuses the list's encoded substitution rather than publishing partial data.
  Only viewport rows are drawn in one child window.
+
Tab/Shift-Tab traverse inputs and lists in definition order. Arrows, Home/End
and Page Up/Page Down move list focus; Space and left click toggle selection.
Shift-navigation or Shift-click adds the inclusive range from the last ordinary
focus position. An extension exceeding 256 selected rows is refused atomically,
including its focus change. Clear selection through the consumer to start again.
Wheel buttons scroll three rows without changing focus. Track clicks above or
below the thumb scroll one viewport. Function keys retain button shortcuts.
Restart restores configured selections/focus. These rules apply to forms with
List; existing forms retain their input/history traversal.

**FvwmForm: ListGrid ``_columns_``*::
  Immediately after List and before any ListItem, choose a grid with 2..8
  columns. List's rows now count visual grid rows. Each column needs at least
  64 actual pixels; checked geometry must fit X coordinates. Left/Right move
  one entry; Up/Down move one visual row; Page Up/Down move one viewport.
  Incomplete final rows contain no selectable blank cells. ListFocus and the
  encoded bitmap continue to use entry indices, independent of presentation.
  Invalid layout refuses the list result. Omit this directive for the list.

**FvwmForm: ListViewport ``_minimum_cell_units_ _maximum_columns_``*::
  Immediately after List, opt into one expanding collection line per Form.
  The List must occupy its own Line, with no other items on that Line.
  Minimum cell width uses 1..4096 ButtonFont units; maximum columns is 1..8.
  Use maximum 1 for compact list rows, or 2..8 for icon-grid cells, retaining
  grid presentation even when only one column fits. Do not combine ListGrid
  and ListViewport. Existing forms without ListViewport keep fixed geometry.
+
List width and rows establish the initial requested size. Resizing the Form
reflows the existing list window into the available content width and height,
with at most 32 visible rows and the configured column maximum. Padding and
the scrollbar are excluded before calculating cells. Labels remain clipped.
Fixed lines before and after the viewport retain their controls and move with
the available space. Minimum size hints reserve room for those controls and
one collection row; a window manager that overrides these hints can clip them.
The same Form and list windows remain in use. Selection, focused entry,
selection anchor and published snapshot generation do not change on resize.
The old first visible entry remains in the first visual row where possible;
the viewport clamps at the end of the collection. A wheel-scrolled viewport
does not force the focused entry back onscreen during resize.

**FvwmForm: ListItem on | off ``_string_`` [file | directory | link | other]*::
  Append one quoted presentation label (at most 1024 source bytes including
  quotes) to the preceding List. The optional literal type chooses a native
  monochrome mark scaled from ButtonFont. Grid cells without a type use a
  generic mark. These marks load no files or thumbnails. Labels are clipped to
  their cell; use the consumer's properties view for a long name.
  Labels have no action/path identity. Use only
  nonsensitive metadata: ordinary command and Echo channels are public to the
  user's other modules.

**FvwmForm: ListFocus ``_row_``*::
  Set initial focus to an existing one-based row in the preceding List.

**FvwmForm: ListVersioned*::
  After List and before its entries, opt into live updates and a generation
  prefix in the encoded list callback. Initial generation is 1. Omit this
  directive to keep the original immutable list/callback format. Use unique,
  unquoted, whitespace-free list names for live commands. Fixed lists retain
  their layout; an opted-in ListViewport also accepts live ListLayout changes.

Send the following runtime commands directly to the running form's exact
alias, for example `SendToModule MyFiles ListBegin picks 1 2`.
Direct messages use existing module transport without appending old snapshots
to core configuration. Runtime configuration lines such as
`SendToModule MyFiles ListBegin picks 1 2` remain accepted, but are stored by the core;
prefer direct messages for repeated updates. No new socket, module packet or
toolkit is required. Only nonsensitive presentation metadata belongs in these commands.
Escape presentation text using the same rules as ListItem. Never pass private
clipboard payloads or reconstruct action identity from a label.

**FvwmForm: ListBegin ``_name_ _expected_ _generation_``*::
  Stage one complete replacement snapshot for the named versioned list.
  Expected must equal its published generation. The new generation must be
  greater than every previously admitted transaction, including aborted ones,
  and at most 2147483647. There is one pending snapshot per list; another Begin
  is refused until Commit or Abort. Refusal leaves the current view intact.

**FvwmForm: ListEntry ``_name_ _generation_ _source_ _string_`` [file | directory | link | other] [keep | on | off]*::
  Append a quoted label/type to the pending snapshot, in its new display order.
  Source is the entry's one-based index in the published snapshot, or 0 for a
  new entry. A nonzero source must exist and appear at most once. The domain
  owner supplies this identity mapping using stable IDs; label equality does
  not establish identity. The optional choice after a type mark overrides
  selection at commit: on selects, off clears, keep preserves current selection
  through source identity. Default keep leaves new entries unselected. Explicit
  on can restore an entry selected while filtered out. Commit refuses a result
  above 256 selected entries atomically. Limits are 4096 entries
  and the same 1024 source-byte label bound as ListItem.
+
An invalid entry addressed to the pending generation poisons that candidate;
Commit then refuses the whole update. Abort discards it. Records for another
generation cannot append to, poison or abort the current candidate. No partial
candidate is drawn or substituted into commands.

**FvwmForm: ListCommit ``_name_ _generation_``*::
  Publish the complete staged snapshot atomically. Preserve current selection
  through source identity, including user changes made after Begin. Surviving
  focus and range anchor move with their entries. Removed focus uses the next
  surviving old neighbor, then the previous one, then the first new entry.
  The old viewport anchor follows the same rule, aligned/clamped for list/grid;
  an offscreen focus does not force scrolling. Removed selections disappear.
  An empty snapshot clears the collection. The same X child/windows, input
  drafts and fixed geometry remain. Restart now restores this published state.

**FvwmForm: ListFocus ``_name_ _generation_ _row_``*::
  Runtime command for a named versioned list/grid, distinct from the initial
  one-argument ListFocus directive. Require its current positive generation and
  an existing one-based row. Set focus/anchor and scroll the row into view,
  preserving selection, input drafts, geometry and X windows. Refuse stale or
  out-of-range requests, refused lists and lists with a pending update; refusal
  changes neither published state nor staging. Restart uses the accepted focus.
  Send through `SendToModule Alias ListFocus picks 2 32` and observe native
  `ListStatus picks token selection` before releasing the old identity map.

**FvwmForm: ListLayout ``_name_ _expected_ _next_ _cell_units_ _maximum_columns_``*::
  Change the prepared, versioned ListViewport's presentation in the running
  Form. Expected must equal its positive published generation. Next must be
  greater than every admitted snapshot or layout generation, including aborted
  snapshots, and at most 2147483647. Cell units use the same 1..4096 ButtonFont
  units as ListViewport; maximum columns is 1..8. Maximum 1 chooses compact
  list rows, while 2..8 chooses icon-grid cells even when one column fits.
  Fixed lists, unversioned lists, pending snapshot updates, stale generations,
  malformed arguments and unrepresentable geometry refuse the entire operation.
+
Reflow keeps the current Form size and refuses if it cannot contain the new
minimum cell width, fixed controls and one complete row. Enlarge the Form and
retry with the unchanged expected generation after such a refusal. Minimum
size hints change with the admitted cell width and row height.
The Form, collection child and controls retain their X windows. Entry content,
input drafts, active input/list focus, focused entry, range anchor and selection
remain. The old top entry stays in the first visual row where possible, with
edge clamping; an intentionally offscreen focused entry stays offscreen.
The complete admitted layout advances the published generation, so callbacks
from the preceding layout are stale. Restart restores this accepted state.
For example, send `SendToModule MyFiles ListLayout picks 2 3 18 8`, then
`SendToModule MyFiles ListStatus picks layout_3 selection`. Wait for the actual
native reply reporting published 3, pending 0 and its generation-3 selection
packet before advancing the consumer's mode/generation. Refusal leaves the
published state, pending transaction and controls unchanged.

**FvwmForm: ListAbort ``_name_ _generation_``*::
  Discard the matching pending snapshot and free its labels. A discarded
  generation cannot be reused. Pending resources are also freed on module exit.
  Staging has a fixed entry/label bound, with no automatic expiry: its owner
  must finish or abort a transaction, or close the form.

**FvwmForm: ListStatus ``_name_ _token_`` [selection]*::
  Ask the native module to emit `Echo FVWM_FORM_LIST token published pending refused`.
  Token is 1..64 ASCII letters/digits, hyphen or underscore. Published is the
  current generation; pending is 0 when no update exists; refused is 1 for a
  poisoned candidate, otherwise 0. With the optional literal selection word,
  append `x` followed by the current versioned list's URL-base64 packet. This
  observes native input made during staging without changing it. The original
  five-field reply remains unchanged when that word is omitted.
  Wait for this native reply after Commit, ListLayout or
  Abort before advancing the consumer's published mapping. A core Echo alone
  acknowledges core command processing, not native publication. Unknown or
  ambiguous names and malformed commands produce diagnostics; a consumer must
  bound its wait and handle missing replies/module death.

**FvwmForm: UIScaleStatus ``_token_``*::
  Query native scale state without changing the view, for example
  `SendToModule MyFiles UIScaleStatus scale_1`. Token is 1..64 ASCII
  letters/digits, hyphen or underscore, as for ListStatus. The native reply
  is one line with these fields in order:
+
....
FVWM_FORM_UI_SCALE token enabled state current_q desired_q current_epoch desired_epoch current_atom desired_atom resource_gen min_w min_h required_w required_h
....
+
Enabled reports whether the opt-in composition was admitted, as 0 or 1. State is one of disabled,
unsupported, waiting, deferred, refused or ready. Current and desired factors
are expressed in quarters: 4 is 1x, 5 is 1.25x, 6 is 1.5x and 8 is 2x.
Epochs are 16 lowercase hexadecimal digits, or all zeros when unavailable;
atoms identify the selected monitor. Resource_gen is the existing font/cache
resource generation, separate from the scale factor; moving between monitors
does not imply that it increments. Min_w/min_h describe the current minimum,
and required_w/required_h the prepared minimum, in actual pixels. Required
values are zero when the desired target has not completed geometry preparation.
+
The current fields describe the retained view. Desired fields alone do not
establish publication: a deferred or refused update can retain the preceding
complete view. This status is separate from ListStatus and its native
collection generation; consumers must keep the existing list acknowledgement
rules. Bound waits and handle module loss or missing replies explicitly.

**FvwmForm: RenewTimeout ``_ticks_``*::
  Renew an already active Timeout through `SendToModule MyForm RenewTimeout 3000`.
  Ticks are 1..99999 tenths of a second. The configured command and timer cadence
  stay unchanged; a missing or already dispatched timeout cannot be resurrected.
  A live consumer can refresh its finite orphan deadline while preserving its
  window. Stopping renewal still permits expiry and module cleanup.

**FvwmForm: ListNotify ``_token_``*::
  After ListVersioned, configure one startup observation for that list. Token
  uses ListStatus's literal bound. Once the native Form is initialized, emit
  the same reply as ListStatus with selection. This is a native readiness
  handshake; it does not activate an application. Preload forms retain their
  existing unmapped startup behavior.

**FvwmForm: ListWatch ``_watch_token_``*::
  After ListVersioned, opt the current list into interactive change notification.
  The token follows the ListStatus token grammar (1..64 ASCII letters/digits,
  hyphen or underscore). Watching is off by default. When user input actually
  changes focus index, selection or viewport position, the Form sends
  `Echo FVWM_FORM_CHANGED watch_token` once and latches further notifications.
  Programmatic changes, redraws, status queries and unchanged or clamped input
  do not emit a notification. The marker is an invalidation, not a selection
  packet or authority to perform an action.

**FvwmForm: ListWatchStatus ``_name_ _watch_token_ _request_token_``*::
  Ask the named versioned list for its current status and selection, and rearm
  its watch in the same native handler. Both tokens use the ListStatus grammar;
  the watch token must match the configured subscription exactly. The reply is
  `FVWM_FORM_LIST request_token published pending refused xpacket`, with the
  same fields and URL-base64 selection packet as `ListStatus ... selection`.
  Changes before this handler are included in its snapshot; a subsequent user
  change can emit a new marker. Malformed requests, wrong tokens and failed
  reports do not rearm. Ordinary ListStatus and startup-only ListNotify do not
  rearm either.
+
A consumer should bind the watch token to the Form lifetime, coalesce markers,
request a fresh correlated snapshot and resolve indices only through the current
acknowledged generation. Bound the wait and handle missing replies or module
loss; a marker alone does not prove delivery of a snapshot. Retire old tokens
when the Form closes or is replaced. Consumers that do not configure ListWatch
can continue to use ListNotify and explicit ListStatus queries.
+
For example, configure a versioned list and acknowledge each change:
+
----
*MyFiles: List picks 64 6
*MyFiles: ListVersioned
*MyFiles: ListWatch my_form_1
*MyFiles: ListItem off "First" file
Module FvwmForm MyFiles
# On FVWM_FORM_CHANGED my_form_1, request a fresh correlated snapshot:
SendToModule MyFiles ListWatchStatus picks my_form_1 request_1
----

For example, start a two-entry live list, then reorder it and insert a new row:

----
*MyFiles: Line left
*MyFiles: List picks 64 6
*MyFiles: ListVersioned
*MyFiles: ListItem on "First" file
*MyFiles: ListItem off "Second" directory
*MyFiles: Line left
*MyFiles: Button continue "Inspect" F2
*MyFiles: Command Echo MY_COLLECTION x$(picks:Base64)
Module FvwmForm MyFiles
# Once MyFiles is running, send:
SendToModule MyFiles ListBegin picks 1 2
SendToModule MyFiles ListEntry picks 2 2 "Second, updated" directory
SendToModule MyFiles ListEntry picks 2 0 "New entry" file
SendToModule MyFiles ListEntry picks 2 1 "First" file
SendToModule MyFiles ListCommit picks 2
SendToModule MyFiles ListStatus picks example_2
----

The selected First entry becomes row 3. Upload long snapshots in bounded,
acknowledged batches through the existing transport. A core acknowledgement
bounds core input; use native ListStatus replies to bound the target module
queue and prove that each batch was consumed. Accept callbacks only
against the exact form identity and the published generation; reject stale
indices before resolving domain IDs. This primitive does not automatically
connect a filesystem watcher, update other form text or manage a provider.

**FvwmForm: Selection ``_name_ _type_``*::
  This option starts a selection item with name _name_. Its choices are
  specified in following configuration commands. The option _type_ is
  one of the following:
+
*``_single_``*:::
  The selections are mutually exclusive.
+
*``_multiple_``*:::
  This is a multiple-choice selection.

**FvwmForm: Separator*::
  Draws a 2 pixel shaded line across the form as a visual indication of
  a separate area.

**FvwmForm: Choice ``_name_ _value_`` on | off ``_string_``*::
  Specifies a choice for a proceeding selection. The choice item has a
  _name_ and a _value_ these are used in commands. See *FvwmForm:
  Command. The _string_ is displayed to the right of the choice button
  as a label.
+
The choice assumes the specified initial state ("on" means selected)
when FvwmForm starts or resets. If the selections are mutually
exclusive, FvwmForm does NOT detect inconsistencies in the initial
states of the choices, i.e. two or none of the choices can be selected.
However, once the user selects a choice, FvwmForm assures only one is
selected.

**FvwmForm: Button ``_type_ _string_`` [``_key_``]*::
  This option specifies an action button. The button has _string_ as a
  label, and executes a set of Fvwm _command_ when it is activated. The
  commands are the following *FvwmForm: Commands.
+
The optional _key_ specifies a keyboard shortcut that activates the
button. It can be a control character, specified as ^@, ^A, ...,
^_, a function key, specified as F1, F2, ..., F35, or an Alt shortcut,
specified as Alt-F or Alt-1. Alt shortcuts accept exactly one ASCII letter
or digit; letters and the Alt prefix are case-insensitive. An invalid Alt-
shortcut ignores the button with a diagnostic. Control keys that
are used for cursor movement in text input fields cannot activate any
buttons, with the exception of TAB (^I), RETURN (^M), LINEFEED (^J),
which can activate a button when the cursor is in the last text input
field.
+
Configured Alt shortcuts work while either a text input or collection has
focus. They require the X11 Mod1 modifier and no Control or Mod4 (the usual
Super modifier). Shift and Caps Lock can change a letter's case. The first
defined matching button activates through its ordinary command path, without
inserting the shortcut into a draft or changing collection focus/selection.
Unmatched Alt keys retain the existing text-input and collection behavior.
Show the shortcut in the button's label when users need to discover it.
+
Put the label in double quotes.
Use a backslash before a double quote to include it in the label.
The key follows the closing quote.
An incomplete quoted label is ignored.
+
The behavior of the button is determined by _type_:
+
continue:::
  FvwmForm continues execution after sending the commands.
restart:::
  After sending the commands, FvwmForm resets all the values to the
  initial ones, and then continues execution.
quit:::
  FvwmForm quits after sending the commands.

**FvwmForm: CloseCommand ``_command_``*::
  Send one literal FVWM command when the form accepts a WM_DELETE_WINDOW
  request, then exit. There is no close command by default. The command must
  contain non-whitespace text and fit the module command limit of 1000 bytes.
  An invalid replacement leaves the previous close command in effect.
+
The command is sent through FVWM's command engine without FvwmForm field
substitution or special handling of a leading exclamation mark. Do not quote
the complete command. For example:
+
....
*MyForm: CloseCommand SendToModule MyController form-closed
....
+
This option does not change quit-button actions. It does not run for
KillModule, provider loss, signals or transport errors, and is not a general
shutdown cleanup hook.

**FvwmForm: Command ``_command_``*::
  This option specifies an Fvwm command associated with the current
  button. There can be more than one command attached to a button.
  Commands that appear before any *FvwmForm: Button option are executed
  at start-up time. This is usually a beep that gets the user's
  attention.
+
Commands starting with an exclamation mark (!) are executed by FvwmForm,
all other commands are sent to Fvwm for execution. Before sending each
command to Fvwm, FvwmForm recognizes variables of the following forms,
and supply values to them.
+
An incomplete variable expression is refused.
A refused button command is skipped, and later commands remain usable.
A refused timeout command keeps the form open.

*$(``_name_``)*::
  If _name_ corresponds to a text input field, the result is the user's
  input string. The result uses the input string's exact bytes.
+
If _name_ corresponds to a choice, the result is its configured value
(as specified in *FvwmForm: Choice). Use a conditional form to check
whether the choice is selected.
+
If _name_ corresponds to a selection, the result will be a list of the
selected values of all its choices separated by spaces.

*$(``_name_``?``_string_``)*::
  If _name_ is a text input field and its value is not an empty string,
  the result is _string_, with recursive variable substitution applied.
  If the input value is empty, the result is empty.
+
If _name_ is a choice and it is selected, the result is _string_, with
recursive variable substitution applied. If the choice is not selected,
the result is empty.

*$(``_name_``!``_string_``)*::
  The same as the above, except that the converse conditions are taken.
+
When using the "?" and "!" forms to pass a string, the string is
delimited by a right parenthesis. If you need to put a right parenthesis
in a string, precede the right parenthesis with a backslash.

*$(``_name_``:Base64)*::
  Encode the field's exact bytes as URL-base64 without padding. The result
  contains letters, digits, `_` and `-`. Input and choice values can contain
  at most 65536 bytes. A selection encodes its space-separated selected values.
  Refuse a larger value. Quote the substitution when an empty result must
  remain one shell argument. This encoding does not execute the field value.
+
For List, this explicit modifier encodes a binary packet: two bytes of
zero-based focus in big-endian order, then ceil(row-count/8) selection bytes.
Bit 0 of the first selection byte is row 0; unused tail bits are zero. Empty
lists use focus zero and no selection bytes. The maximum is 514 raw / 686
encoded bytes. With ListVersioned, prepend four big-endian generation bytes;
the maximum is then 518 raw / 691 encoded bytes. Ordinary List substitution
is empty. Consumers must validate
length, padding, focus, selection cap and the exact immutable view generation
before resolving row indices to domain IDs. Do not use labels as IDs.
+
An existing field named `_name_:Base64` takes priority and keeps its ordinary
value. Plain substitutions and choice conditions keep their existing behavior.

*$(``FormJob:Token``)*::
  Return a 16-digit hexadecimal serial for the current button invocation.
  All commands on that button receive the same serial. The next invocation
  receives another serial. Use this with a unique form-session prefix for
  private result files. An existing field with this full name takes priority.

**FvwmForm: CommandAppend ``_text_``*::
  Add one space and _text_ to the preceding command on the current button.
  This permits a template to use several module configuration records.
  The complete template can contain at most 1 MiB. If it exceeds the limit,
  refuse the button's commands. Values substituted later are still subject
  to the command's execution and argument limits.

**FvwmForm: InputAppend "``_text_``"*::
  Add quoted text to the preceding Input's initial value. This permits long
  initial values to use several module configuration records. The complete
  initial value can contain at most 65536 bytes. On refusal, keep the preceding
  value. Reset uses the complete initial value.

**FvwmForm: UseData ``_datafile_ _leading_``*::
  Tells FvwmForm to read a data file and extract data from module
  commands that match the "leading" argument and an input, choice, or
  selection variable in a form.
+
The data file and prefix are required.
An incomplete UseData line keeps the previous values.
The read request preserves the filename within the module command limit.
+
This lets a form display current fvwm module configuration data. For an
example of how this works, examine the file "FvwmForm-Rlogin" which is
installed in read-only architecture-independent data directory,
[PREFIX/share/fvwm] and shown below.
+
For choices, the setting of the button is represented as the word "on",
all other values for a setting are treated as off.
+
For selections, the setting of each choice button is determined by
matching the current value of the selection against each choice.
Currently, this only works correctly for selections that allow a single
choice.

**FvwmForm: ButtonPointer ``_pointername_``*::
  Change the default mouse pointer (hand2) used when hovering over a
  button. The pointername must be one of the names defined in the
  include file X11/cursorfont.h (without the XC_ prefix). See DEFAULTS.

**FvwmForm: ButtonInPointer ``_pointername_``*::
  Change the default mouse pointer (hand1) used while a button is
  pressed in. The pointername must be one of the names defined in the
  include file X11/cursorfont.h (without the XC_ prefix). See DEFAULTS.

**FvwmForm: InputPointer ``_pointername_``*::
  Change the default mouse pointer (xterm) used while the pointer is
  over a text field. The pointername must be one of the names defined in
  the include file X11/cursorfont.h (without the XC_ prefix). See
  DEFAULTS.

**FvwmForm: ButtonPointerFore|Back ``_color_``*::
  Change the default mouse pointer foreground and background colors used
  when hovering over a button. See DEFAULTS.

**FvwmForm: ButtonInPointerFore|Back ``_color_``*::
  Change the default mouse pointer foreground and background colors used
  while a button is pressed in. See DEFAULTS.

**FvwmForm: InputPointerFore|Back ``_color_``*::
  Change the default mouse pointer foreground and background colors used
  while the pointer is over a text field. See DEFAULTS.

**FvwmForm: Timeout ``_tenth_of_seconds_ _command_`` ``_"text"_``*::
  Set up FvwmForm to time out after the amount of _tenth of seconds_
  specified. When the timer hits zero, _command_ executes. The _text_
  field is displayed much like a _Text_ field, except that a '%%' in the
  line is replaced automatically by the amount of time left on the
  timer. The value gets updated every tenth of second as the timer
  counts down. There can only be one timeout field per form.
  The form processes input and module commands while the timer runs.
  A Timeout directive with missing command or text arguments, or an incomplete
  quoted argument, is ignored. It does not use the form's timeout field.

== EXAMPLES

All of the following "examples" are installed in the read-only
architecture-independent data directory, [PREFIX/share/fvwm], during
fvwm installation.

The following commands create a menu to invoke the examples:

....
DestroyMenu Forms

....

== EXAMPLE 1 - Quit Verify

This example simulates the mwm way of confirming logout. Return does the
logout, Escape cancels logout. It times out after 20 seconds and
performs the equivalent of the 'Logout' button.

....
DestroyModuleConfig  FvwmForm-QuitVerify: *
*FvwmForm-QuitVerify: GrabServer
*FvwmForm-QuitVerify: WarpPointer
*FvwmForm-QuitVerify: Command     Beep
*FvwmForm-QuitVerify: Line        center
*FvwmForm-QuitVerify: Text        "Do you really want to logout?"
*FvwmForm-QuitVerify: Line        expand
*FvwmForm-QuitVerify: Button      quit "Logout" ^M
*FvwmForm-QuitVerify: Command     Quit
*FvwmForm-QuitVerify: Button      restart   "Restart" ^R
*FvwmForm-QuitVerify: Command     Restart
*FvwmForm-QuitVerify: Button      quit "Cancel" ^[
*FvwmForm-QuitVerify: Command     Nop
*FvwmForm-QuitVerify: Timeout     200 Quit "Automatic logout will occur in %% tenth of seconds."
....

*FvwmForm-Rlogin: Input        UserName        10      ""
*FvwmForm-Rlogin: Line         expand

term@$(HostName) -display $HOSTDISPLAY &

== BUGS AND LIMITATIONS

FvwmForm is a fairly simple method of providing input. There is no input
validation facility. FvwmForm has no way of dealing with lists.

Report bugs to the fvwm-workers list.
