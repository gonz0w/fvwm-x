== NAME

fvwm-file-browser - bounded native folder-browser foundations

== SYNOPSIS

*fvwm-file-browser* [*--dir* _local-target_] [*--hidden*]
[*--view* list|grid] [*--socket* _path_] [*--opener* _executable_] [*--terminal* _executable_]

*fvwm-file-browser* *--reveal* _local-target_ [*--reveal* _local-target_ ...]
[*--view* list|grid] [*--socket* _path_] [*--hidden*]

*fvwm-file-browser* *--properties* _local-target_ [*--view* list|grid]
[*--socket* _path_] [*--hidden*]

*fvwm-file-browser* *--inspect* [*--dir* _local-target_] [*--hidden*]

== DESCRIPTION

This optional Go helper presents local folders with existing FvwmForm controls
and the current FvwmMFL connection. Start Module FvwmMFL first. No GUI toolkit,
compositor, D-Bus service or background daemon is required. List and icon-grid
presentations scroll locally through up to 4096 entries. The list has twelve
visible rows; the grid has four rows of four cells. Only visible entries are
drawn in one native window. Existing
folder menus and user configurations stay usable.

The shared collection model separates stable item IDs from labels, preserves
surviving selections across refresh and admits at most 4096 entries and 256
selected items. Filesystem names remain original bytes, including non-UTF-8
names. This first consumer shows non-ASCII, control and expansion characters as
ASCII [U+XXXX] escapes; labels may be shortened. Labels are never
used to reconstruct paths or executable commands. Symlinks and special files
are listed but activation is unavailable in this checkpoint.

All enumeration, metadata checks and application dispatch run in one separate
worker process. There is one active child and at most one replacement navigation
request. Supersession or Cancel requests termination; the slot remains owned
until the child is reaped. Each worker has a ten-second deadline. A kernel call
that cannot be interrupted can delay reaping, so a timeout is not a promise of
instant termination. The WM and browser control loop do not perform those calls.
Over-limit folders are refused as a whole, including hidden entries in the
budget; there is no silent truncation before sorting.

== CONTROLS

Tab and Shift-Tab move among the filter, collection and path fields. In the list,
Up/Down, Home/End and Page Up/Page Down move focus and reveal that entry.
Grid Left/Right move one entry; Up/Down move four entries. Shift-navigation
or Shift-click adds the inclusive range from the last ordinary focus position.
An over-limit range leaves focus and selection unchanged. Space
toggles its selection; clicking a row also toggles it. Wheel scrolling changes
the viewport without changing focus or selection. Clicking the track above or
below its thumb scrolls one viewport. Open focused (Enter) acts on the focused
row independently of the selection. Open selected (F3) requires exactly one selected
item. Directories load in the same browser. Files start the configured opener
with one literal absolute-path argument; no shell evaluates a filename.
Application started means process creation succeeded, not that the application
opened a window or finished.

View (F7) switches list/grid without changing the model, focused ID or selected
IDs. `--view list|grid` chooses the initial presentation (default list); the
choice lasts for this browser instance and is not saved. Native type marks
identify directories, regular files, links and other entries; they are not
thumbnails or externally loaded themed icons. Labels are clipped within grid
cells; Properties exposes the observed name. Blank cells in the final row have
no target.

Home, Up and Back navigate; Back retains at most 32 successful locations. Path
and Go accept an absolute path or a path relative to the current folder.
Refresh (F5) reloads and Hidden (F6) toggles dot entries. Counters show
visible/loaded items, total selection and the selected count excluded by the
filter. Offscreen and filtered-out selections remain selected. Select visible
selects the complete filtered projection, refusing the whole change if it would
exceed the 256-item total limit. Clear selection also clears filtered-out items. Terminal (F4) starts the
configured executable in the current folder with no extra arguments. These
executables are program paths/names, not shell fragments or argument templates.

Filter and Apply filter perform a case-insensitive literal substring match on
the admitted display labels, not raw paths. The query is valid UTF-8 of at most
128 bytes. No glob, regular expression, recursive search or filesystem access
runs. Clear filter restores all loaded entries. The input starts empty after
each redraw; the active filter is shown separately. Applying an empty input also
clears it. The filter persists across refresh and folder navigation.

Sort cycles through name, kind, size and modified time. The direction button
toggles ascending/descending. Directories remain first in both directions;
primary-key ties use raw filename byte order in the chosen direction. Size is
the observed entry size, not recursive disk usage. These operations reorder the
loaded snapshot without rescanning. Selection uses IDs rather than positions.
Sort preserves a surviving focused ID; filtering chooses the first matching item
when the old focus is excluded. Refresh retains surviving focus and selection,
including filtered-out selections. If focus disappears, the next surviving
visible old neighbor receives focus, then the previous one, otherwise the first
new visible item. The focused item is revealed when the native view is rebuilt;
a wheel-only viewport position is not retained across that rebuild.

Refresh reports added, updated and removed entry counts and the number of
selected entries that disappeared. Counts compare directory-entry identities
and observed type, mode, size and modification time. A changed identity counts
as a removal and addition. No file content is read.
An unchanged refresh reports no entry metadata changes. A small change publishes
one generation-checked metadata transaction; a larger change publishes one
bounded validated replacement. Neither path publishes a partial collection.
The filter, presentation and surviving IDs remain intact. Native controls are
still rebuilt as a complete view; file watching is not enabled.

Properties (F2) requires exactly one selected item, including a selection on
another page or excluded by the filter. It displays the name, kind, mode,
observed byte size and modification time in UTC from the last successful scan.
It does not query the filesystem, follow symlinks, inspect content or validate a
currently actionable target. Refresh updates the observation. Opening a file
still uses the isolated worker's separate identity validation.

Cancel work invalidates the pending result and requests worker termination.
Close (Escape) exits the helper and closes its Form. The prototype closes after
five minutes without a callback; it also has an independent native Form timer.
Closing through the window manager can leave the helper until its idle deadline.
SIGINT/SIGTERM cancel work and close the owned Form. Connection loss ends the
helper; a remaining Form expires independently. This is a bounded example
consumer, not a persistent full file-manager window.

Every rendered Form has a fresh callback generation. Old controls cannot act
on a newer view. Target actions recheck directory and entry identity immediately
before dispatch; replaced/missing/changed items require refresh. Passing a path
to another application cannot guarantee that the path stays unchanged afterward.
This observation contract is unsuitable for destructive file jobs, which remain
unavailable here. No copy/move/delete, trash, automatic watching, recursive search,
thumbnail service or encrypted clipboard storage is implemented.

== PORTABLE TARGET REQUESTS

A local target is an absolute filesystem path or a local file URI. An ordinary
absolute path is literal, including percent, question-mark and hash characters.
URI percent escapes are decoded exactly once and retain original filename bytes,
including non-UTF-8 bytes. Empty authority or localhost is supported; remote
hosts, user information, ports, opaque/relative URIs and raw query/fragment
syntax are refused. Encode filename question marks and hashes as %3F and %23.
Decoded paths must be absolute, contain no NUL and fit the 4096-byte path limit;
encoded target arguments are bounded before decoding. OS argument limits also
apply to a launch request.

Choose --dir, repeated --reveal, or one --properties. The forms are mutually
exclusive. --reveal loads the common parent and selects one to 256 requested
entries, bringing the first requested entry's page into view. It never executes
or opens the targets. A requested dot entry automatically enables hidden entries.
Duplicate targets, mixed lexical parents, root targets, dot path components and
missing entries fail as a whole; no partial selection is published. Repeated or
trailing separators are normalized for reveal/properties. Use --dir / to browse
the filesystem root. Symlinks and special files may be revealed and inspected;
their activation remains unavailable.

--properties selects one entry in its parent and immediately shows the observed
properties panel. Target resolution, including parent enumeration, runs in the
same isolated cancellable worker. The whole parent's admission limit still
applies. These are portable launch requests for separate browser instances,
not a single-instance daemon, FileManager1 service, new default folder handler
or general structured MFL files provider.

== OPTIONS

*--dir* _local-target_::
  Initial folder, default the user's home directory. Paths are at most 4096
  bytes. Folder ordering is directories first, then raw filename byte order.

*--view* list|grid::
  Initial native presentation. Default list. F7 switches it without changing
  item IDs, focus or selection. The choice is not persisted.

*--hidden*::
  Include dot entries. Default off; an explicitly revealed dot entry enables it.

*--reveal* _local-target_::
  Reveal an existing entry in its parent; repeat for bounded targets in one folder.

*--properties* _local-target_::
  Reveal one entry with its last observed properties shown immediately.

*--socket* _path_::
  Explicit FvwmMFL Unix socket. Otherwise use FVWMMFL_SOCKET, then the normal
  FVWMMFL_SOCKET_PATH / XDG_RUNTIME_DIR / private temporary-directory discovery
  used by FvwmCommand. DISPLAY selects the endpoint. No network listener opens.

*--opener* _executable_::
  File-opening program; default xdg-open when found. Missing capability reports
  unavailable without executing a fallback shell. The absolute file path is
  passed as one argument.

*--terminal* _executable_::
  Terminal program; default x-terminal-emulator, then xterm when found.

*--inspect*::
  Run the same isolated scanner without X and emit one schema-version-1 JSON
  result. Path/name byte fields are standard padded base64 JSON strings. A loaded
  snapshot contains the root observation, hidden flag and stable item IDs with
  kind and metadata. Failure emits a failed result and exits nonzero. This is
  file metadata, not a protected-content or clipboard payload channel. It also
  accepts --reveal or --properties instead of --dir, emitting selected_ids in
  requested order on success. A missing target emits a failed result with no
  snapshot or selection. Invalid syntax/option combinations fail before work.

*--help*::
  Show command usage. Unknown options/extra operands fail.

== CONFIGURATION EXAMPLE

The optional executable installs with Go-enabled builds. A working independent
consumer can be opened from a binding without replacing the default folder menu:

----
AddToMenu FileTools "Folder browser" Exec exec fvwm-file-browser
Key F9 A M Exec exec fvwm-file-browser
----

Explicit target examples (no target is executed by reveal/properties):

----
fvwm-file-browser --reveal /home/user/Documents/report.txt
fvwm-file-browser --properties file:///home/user/Documents/report%20draft.txt
fvwm-file-browser --inspect --reveal /home/user/Documents/report.txt
----

The browser uses a random per-process Form alias and existing Form defaults.
Personal FvwmForm defaults may set fonts/colors. It does not change theme or
core window policy. Run the executable directly in an FVWM session for an
initial folder whose name needs literal shell argument quoting.

== OWNERSHIP AND LIMITS

The collection package owns metadata/selection only. The file adapter owns raw
names, directory observations and actions. Reusable metadata policy does not
qualify clipboard payload lifetime or protection. Sensitive clipboard data must
not be routed through ordinary Form command expansion or MFL Echo broadcasts.

Native callbacks use the existing Echo/MFL framing with a versioned marker,
instance/view identity and a known action. A bounded row-index selection bitmap
and focus are URL-base64 encoded; the model resolves them only against the exact
rendered projection. Paths use the existing encoded input field. Configuration
uploads are paced in batches of at most 32 commands with core acknowledgements
and a ten-second total acknowledgement deadline. These are stale-control guards, not
same-user or X11 authorization. No general IPC files provider is advertised by
this first consumer. Broader structured providers, incremental updates and the
complete file-browser handoff remain with FILE-VIEW/DATA/ACTION-01.

No preferences or directory history are written to disk. Raw metadata remains
in the helper's ordinary Go memory; no secret-storage claim is made. Results and
queues have finite limits, including a 4 MiB private worker envelope and sixteen
native callback slots. Slow/broken MFL output closes the session according to
its existing bounded transport policy. Native GUI and external application
accessibility/interoperability need their own acceptance.

== EXIT STATUS

Zero means the consumer closed normally or inspection loaded. Nonzero means
invalid arguments, unavailable MFL connection, inspection/worker failure or
transport failure. A failed UI action is shown in the browser and can be retried
after refresh; it does not necessarily terminate the consumer.
