:doctype: manpage
:manmanual: FVWM-X Manual

== NAME

fvwm-file-browser - bounded native folder browser and file jobs

== SYNOPSIS

*fvwm-file-browser* [*--dir* _local-target_] [*--hidden*]
[*--view* list|grid] [*--watch* off|auto] [*--socket* _path_]
[*--opener* _executable_] [*--terminal* _executable_]
[*--action* _label=executable_] ...

*fvwm-file-browser* *--reveal* _local-target_ [*--reveal* _local-target_ ...]
[*--view* list|grid] [*--watch* off|auto] [*--socket* _path_] [*--hidden*]

*fvwm-file-browser* *--properties* _local-target_ [*--properties* _local-target_ ...]
[*--action* _label=executable_] ... [*--view* list|grid]
[*--watch* off|auto] [*--socket* _path_] [*--hidden*]

*fvwm-file-browser* *--inspect* [*--dir* _local-target_] [*--hidden*]

*fvwm-file-browser* [*--reuse*] [_local-folder_]

*fvwm-file-browser* *--reuse* [*--dir* _local-folder_]
[*--reveal* _local-target_ ... | *--properties* _local-target_ ...]
[*--socket* _path_]

== DESCRIPTION

This optional Go helper presents local folders with existing FvwmForm controls
and the current FvwmMFL connection. Start Module FvwmMFL first. No GUI toolkit,
compositor, D-Bus service or background daemon is required. List and icon-grid
presentations scroll locally through up to 4096 entries. The initial list requests eight
visible rows; the grid requests three rows. Resize the window to expand or
shrink the collection: the grid fits up to eight columns and both views fit
up to 32 visible rows. Only visible entries are drawn in one native window.
Resizing keeps that window, selection, focused entry and snapshot generation;
the first visible entry stays in the top visual row where possible. Fixed
controls set the minimum window size. Existing
folder menus and user configurations stay usable.

Every browser Form opts into FvwmForm's `UIScale monitor` policy. Its controls,
collection cells and spacing follow the core's effective monitor scale using
the window's actual position, without scaling file content or client pixels.
Moving between monitors or receiving a committed monitor update reflows the
existing native view while retaining input drafts, active control, selection,
focus, range and viewport anchors. Automatic scaling does not advance the
collection generation or replace F7's native layout acknowledgement.
If a larger minimum needs more room, the current complete view remains until
the requested window resize actually arrives; list transactions also defer
scale publication until they finish. Font preparation failure retains the
previous view. Fixed bitmap font aliases may keep their native glyph size;
use scalable fonts for fractional text sizing. See FvwmForm(1) for the scale
policy, fallback and native status query.

The shared collection model separates stable item IDs from labels, preserves
surviving selections across refresh and admits at most 4096 entries and 256
selected items. Filesystem names remain original bytes, including non-UTF-8
names. This first consumer shows non-ASCII, control and expansion characters as
ASCII [U+XXXX] escapes; labels may be shortened. Labels are never
used to reconstruct paths or executable commands. Symlinks and special files
are listed but activation is unavailable in this checkpoint.

Navigation enumeration, metadata checks and application dispatch run in one
separate worker process. File mutation uses a separate owned child described
under FILE JOBS below. There is one active child and at most one replacement navigation
request. Supersession or Cancel requests termination; the slot remains owned
until the child is reaped. Each worker has a ten-second deadline. A kernel call
that cannot be interrupted can delay reaping, so a timeout is not a promise of
instant termination. The WM and browser control loop do not perform those calls.
Over-limit folders are refused as a whole, including hidden entries in the
budget; there is no silent truncation before sorting.

Browser status and metadata labels use the available parent width and show a
complete-character prefix with `...` when text still overflows. Selection and
hidden counts, the selection limit, action availability and refresh or retry
guidance precede variable detail where applicable. The progress label reports an unknown total while the worker checks or
enumerates a target. A successful snapshot reports the loaded entry count;
there is no estimated percentage. The action-readiness label reports openable
visible items and observed properties, terminal and configured-action readiness.
Interactive list focus, selection and scrolling trigger a coalesced native
snapshot; the selection, hidden count and readiness labels update without a
button callback. The browser resolves that snapshot through the current
acknowledged mapping. If the combined hidden and visible selection exceeds 256,
it retains the last admitted model and native selection and reports selection
unavailable. A later valid interaction can recover. Feedback updates labels only;
it does not launch an action or replace the collection. Readiness remains
advisory and each action is validated separately.
These labels describe the current admitted model and provider generation.
Buttons retain their existing appearance; readiness is enforced again by the
backend, including current filesystem identity/type checks before a file action.
During work, after cancellation or after a failed refresh, previous working
entries remain visible but file actions stay unavailable until a fresh snapshot
succeeds. Refresh/navigation can recover without discarding the last working data.
Repeated refresh intents retain one latest pending request; a cancelled or stale
completion cannot replace the current collection or restore action readiness.

== CONTROLS

Tab and Shift-Tab move among the filter, collection and path fields. In the list,
Up/Down, Home/End and Page Up/Page Down move focus and reveal that entry.
Grid Left/Right move one entry; Up/Down move one current visual row. Shift-navigation
or Shift-click adds the inclusive range from the last ordinary focus position.
An over-limit range leaves focus and selection unchanged. Space
toggles its selection; clicking a row also toggles it. Wheel scrolling changes
the viewport without changing focus or selection. Clicking the track above or
below its thumb scrolls one viewport. Open focused (Enter) acts on the focused
row independently of the selection. Open selected (F3) requires exactly one selected
item. Directories load in the same browser. Files start the configured opener
with one literal absolute-path argument; no shell evaluates a filename.
Application started means process creation succeeded, not that the application
opened a window or finished.

View (F7) switches the existing native list/grid viewport without changing the
model, focused ID, selection, range anchor or unsent Path/filter drafts. The
projection label shows the mode after the native collection acknowledges it.
The old top entry stays in the first visual row where geometry permits; edges
clamp to a legal row. Switching does not reveal a wheel-scrolled offscreen
focus. `--view list|grid` chooses the initial presentation (default list); the
choice lasts for this browser instance and is not saved. Native type marks
identify directories, regular files, links and other entries; they are not
thumbnails or externally loaded themed icons. Labels are clipped within grid
cells; Properties exposes the observed name. Metadata labels use bounded
widths, so long paths and status text clip instead of widening the window. Blank cells in the final row have
no target.

Home, Up and Back navigate; Back retains at most 32 successful locations. Path
and Go accept an absolute path or a path relative to the current folder.
Refresh (F5) reloads and Hidden (F6) toggles dot entries. Counters show
visible/loaded items, total selection and the selected count excluded by the
filter. Offscreen and filtered-out selections remain selected. Select visible
selects the complete filtered projection, refusing the whole change if it would
exceed the 256-item total limit. Clear selection also clears filtered-out items. Terminal (F4) starts the
configured executable in the current folder with no extra arguments. These
executables are program paths/names, not shell fragments or argument templates.

Filter and Apply filter perform a case-insensitive literal substring match on
the admitted display labels, not raw paths. The query is valid UTF-8 of at most
128 bytes. No glob, regular expression, recursive search or filesystem access
runs. Clear filter restores all loaded entries without discarding the input
draft; the applied filter is shown separately. Ctrl-U clears the focused input.
Applying an empty input also clears the filter. The filter persists across refresh and folder navigation.

Every browser action has a keyboard shortcut, including while Path/filter input
is focused. Alt-F applies the filter, Alt-C clears the applied filter, Alt-S
cycles sort and Alt-R reverses direction. Alt-A selects visible entries and
Alt-D clears the complete selection. Alt-H, Alt-U and Alt-B navigate Home, Up
and Back; Alt-G submits Path and Alt-X cancels current work. Configured actions
use Alt-1 through Alt-4 in their displayed order. The labels show these keys;
F2 through F9, Enter and Escape retain their displayed actions. Jobs (F9) opens
the captured-selection file-operation dialog. Alt shortcuts
perform actions without inserting their letter/digit into an input. Alt-F and
Alt-G submit their respective draft; other shortcuts preserve unsent input
drafts when the resulting operation retains the current folder/view.

Sort cycles through name, kind, size and modified time. The direction button
toggles ascending/descending. Directories remain first in both directions;
primary-key ties use raw filename byte order in the chosen direction. Size is
the observed entry size, not recursive disk usage. These operations reorder the
loaded snapshot without rescanning. Selection uses IDs rather than positions.
Sort preserves a surviving focused ID; filtering chooses the first matching item
when the old focus is excluded. Refresh retains surviving focus and selection,
including filtered-out selections. If focus disappears, the next surviving
visible old neighbor receives focus, then the previous one, otherwise the first
new visible item. Same-folder refresh, filtering, sorting, selection controls,
properties, list/grid switches and worker-status updates retain the same
Form/native child and unsent input drafts. Surviving viewport/range anchors
follow entry identity; a wheel-scrolled focus does not force scrolling during
live publication.
Navigation to another folder creates a new native view and reveals the focused
item; input drafts reset at that boundary. Exhausting the native generation
counter also requires a new view. If the actual window is too small for the
requested layout, the browser keeps its observed mode, controls and drafts and
asks you to enlarge the window and retry View (F7). It does not report that
requested mode as applied. A malformed, stale or lost native observation retires
the browser lifetime and requires a fresh browser instance.

Refresh reports added, updated and removed entry counts and the number of
selected entries that disappeared. Counts compare directory-entry identities
and observed type, mode, size and modification time. A changed identity counts
as a removal and addition. No file content is read.
An unchanged refresh reports no entry metadata changes. A small change publishes
one generation-checked metadata transaction; a larger change publishes one
bounded validated replacement. Neither path publishes a partial collection.
The filter, presentation and surviving IDs remain intact. Native entries and
fixed status/properties labels update in place; an unchanged refresh leaves
the native entry generation intact. Watching is off by default; see DIRECTORY
WATCHING for opt-in invalidation and consistency limits.

Properties (F2) accepts 1 to 256 selected entries, including offscreen and
filtered-out selections. A single entry shows the observed name, kind, mode,
byte size and modification time in UTC. Multiple entries show counts of regular
files, folders, links and special entries, plus the sum of regular-file sizes.
Folder contents and link targets are not counted. Invalid or overflowing totals
are refused; this is not recursive disk usage. The panel reads the last admitted
snapshot without querying the filesystem or file contents. Its fixed native
area updates without replacing input or collection windows. Refresh updates
the observation; if any inspected identity disappears, the old panel clears.
Opening a file still uses the isolated worker's separate identity validation.

== COMPLETE VALUE DETAILS

Details (F1) opens one read-only snapshot of the admitted browser values:
Path, Status, Watcher, Progress, Readiness, Counts, Projection and the four
Properties panel fields. When available, it also includes the complete focused
filename and single inspected filename from the original filename bytes. The
single-entry Properties name is complete here even when its ordinary label was
shortened. Multiple-entry Properties retain their observed aggregate fields.
No filesystem query or file-content read runs to open or navigate Details.

Tab to the section chooser, use its arrows and press Read (Enter) to display
that field. The value field permits focus, Left/Right and Home/End horizontal
navigation; typing, deletion, paste and history replacement are disabled.
Previous part (F9) and Next part (F10) show the complete value in consecutive
parts, with the field name and part count. Paging retains chooser focus and
continues the displayed field until Read chooses another field. Close (Escape)
or the window manager closes only Details. Reopening F1 replaces the snapshot.
The Details window follows the same monitor scaling policy as the browser.

Values use an unambiguous ASCII display representation: non-ASCII Unicode,
controls, expansion characters and literal brackets become `[U+XXXX]` escapes;
invalid UTF-8 bytes become `[BYTE+XX]`. Concatenating every part gives the entire
escaped value without shortened prefixes. This representation is metadata for
inspection, not file content or a clipboard transfer. Each part has at most
400 ASCII bytes and ends between escape tokens; InputHex installs it literally.
One snapshot admits at most 13 fields, 128 KiB of source bytes, 512 KiB of
escaped text and 1024 parts. Exceeding any bound displays an explicit refusal
instead of a partial snapshot.

Opening, reading and paging Details preserve the browser's native window,
selection, focus, input drafts and model/render/binding generations. Opening
uses the last admitted browser model; it does not capture pending native edits.
The snapshot labels its parent/model/native generations and remains frozen
during same-folder refresh, status changes and local selection changes. Reopen
F1 for the latest admitted values. A replacement parent view or browser exit
retires its Details window and configuration. Retired parent, snapshot, page
and invocation callbacks are ignored.

Accepted Details commands renew the browser's five-minute idle lease. Merely
moving through the chooser or value does not renew the browser lease. Each
Details page also has an independent five-minute native orphan timeout; browser
idle expiry can close it sooner. Details cannot keep a browser alive through
read-only arrow navigation alone. This snapshot adds no metadata freshness or
file-action authority beyond the browser's existing admitted observations.

== CONFIGURED SELECTION ACTIONS

Repeat `--action 'Label=executable'` up to four times to add named native buttons.
Labels are unique valid UTF-8 text of at most 32 bytes. Configured executable
text is also valid UTF-8; selected filenames preserve their original bytes.
The executable is one literal
program name or path; it is not a shell fragment or argument template. Quote a
path containing spaces as part of the option. No configured action runs on
startup. For example:

....
fvwm-file-browser --dir "$HOME" --action 'Edit=gvim'
....

Clicking the button submits the current selected IDs, including filtered-out
selections, from that exact view. With 1 to 256 selected entries, the isolated
worker admits the entire argument list and checks the parent and every selected
entry against its observed identity before starting one process. Each selected
path becomes one literal absolute-path argument, in the current model order;
no label, URI decoding or shell expansion reconstructs an argument. Files and
folders are supported; a link, special entry, missing or changed target refuses
the entire launch. The original filename bytes are preserved. A busy worker
refuses another action rather than queueing a later side effect.

Paths are at most 4096 bytes each and share a 32 KiB argument budget, including
terminators. Oversize selections are refused as a whole. Executable/environment
and operating-system process limits can still cause launch failure. The result
reports process creation and the submitted path count, not application completion.
Path validation is an observation, not a descriptor lease against a later rename;
file mutation jobs require their own contract. Configure only programs whose
selected-path argument interface matches this handoff. The default Open selected
(F3) continues to require one item because generic openers differ in multi-file
support.

== DIRECTORY WATCHING

Watch (F8) toggles automatic refresh; `--watch auto` enables it at startup.
`--watch off` is the default. A fixed status line distinguishes off, starting,
native watching and manual fallback. Automatic updates use the same bounded
snapshot reconciliation as F5, preserving drafts, surviving selection and the
native window. Events do not extend the user's five-minute idle deadline.

One separate observer child owns one directory descriptor and one native event
queue. Linux uses inotify on the already observed directory through procfs;
FreeBSD and OpenBSD use a kqueue directory vnode filter. Filesystem opens,
registration and event reads stay outside the browser/WM loops. The observer
emits at most two change notices per second; the browser coalesces them into one
dirty flag and admits at most one background rescan per second. Navigation and
application work keep the existing worker slot; watching never cancels them or
queues application side effects. A dirty flag waits until that worker is free.

Notifications are advisory. The browser performs a complete rescan after watch
registration and every 30 seconds while watching, including when no native event
arrives. This covers missed changes and child metadata changes not reported by a
BSD directory vnode filter. No per-entry or recursive watches are opened.
While an observer is active or restarting, the browser samples its bounded
state every 100 milliseconds for startup, debounce, lease and reconciliation
work. This sampler stops when watching is off and the observer has exited, or
when an unavailable observer has exited into manual fallback. It produces no
watch timer wakeups for an idle browser in those states. The existing five-minute
idle-close timer remains.
Linux event-queue overflow requests a complete rescan. Changes can still occur
during an observation; explicit Refresh and separate action revalidation remain
available. Watching is not a filesystem journal or a path-identity lease.

Unavailable registration (including missing Linux procfs), observer failure,
directory rename/removal/revocation or failed automatic refresh switches to
manual fallback and retains the previous snapshot. It does not follow a
replacement directory or retry continuously. A successful explicit F5 refresh
or navigation retries an enabled watch; F8 can disable/re-enable it. Cancel work
disables watching and requests cancellation of both owned children, retaining
their process slots until reap. A blocked kernel call can delay reaping.

Observer startup has a ten-second deadline. Each observer has a sixty-second
lease, bounding a quiet orphan if its parent disappears. A live browser renews
by starting the next observer only after the prior one has exited and been
reaped, then rescans after registration. Renewal never extends browser idle
lifetime. Status changes affect the existing label rather than rebuilding the
Form. Inspection (`--inspect`) remains a one-shot snapshot without watching.

== LIFETIME AND TARGET REQUESTS

Cancel work invalidates the pending result, disables watching and requests
worker/observer termination.
Close (Escape) exits the helper and closes its Form. The prototype closes after
five minutes without an accepted callback, control or current-Form feedback;
it also has an independent native Form timer.
Normal window-manager Close, SIGINT/SIGTERM and connection loss cancel owned
work and retain child ownership until reap. A force-killed Form can expire
independently of its helper. A remaining Form has its own orphan lease. This is a bounded example
consumer, not a persistent full file-manager window.

Every rendered Form has a fresh callback generation. Old controls cannot act
on a newer view. Target actions recheck directory and entry identity immediately
before dispatch; replaced/missing/changed items require refresh. Passing a path
to another application cannot guarantee that the path stays unchanged afterward.
File jobs use the separate descriptor-anchored mutation contract below; launch
observations are not reused as mutation authority. Recursive search, thumbnail
services and encrypted clipboard storage remain outside this helper.

== FILE JOBS

Select entries in the browser and choose Jobs (F9). The dialog captures their
literal IDs and observed identities, the source folder, and the selected count
including entries hidden by the current filter. Changing browser navigation or
selection does not silently replace that capture. Reopen Jobs after each admitted
job to capture a fresh selection. There is one active mutation worker and no queue;
ordinary navigation uses its independent worker.

Destination is an absolute folder path, or a path relative to the captured source.
An empty Destination means the source folder. Name is one component, without a
slash: it is required for New folder and Rename, and optionally chooses the
output basename for a *single* Copy, Move or Link target. Leave Name empty for
multiple targets. Trash, Restore and Delete ignore these drafts. Original
filename bytes never come from display labels; typed input/callback fields remain
bounded by the native command transport. Relative destinations avoid resubmitting
long source paths.

[cols="1,1,3",options="header"]
|===
| Key | Operation | Behavior
| F1 | New folder | Creates Name in the captured source folder; selection is not required.
| F2 | Rename | Requires one selected entry and Name.
| F3 | Copy | Copies selected regular files, directories or symbolic links into Destination.
| F4 | Move | Publishes the destination before removing the corresponding source.
| F5 | Link | Creates symbolic links to the observed selected paths; it does not open their content.
| F6 | Trash | Moves into the supported private home-trash area; unavailable trash never becomes deletion.
| F7 | Restore | Restores selected entries from that trash's files folder using their validated metadata.
| F8, then F10 | Permanent delete | F8 previews captured target names; only a later F10 confirms removal. There is no undo.
| Alt-T | Open trash | Opens the home trash's files folder. Select entries there and reopen Jobs for Restore.
| F11 | Skip conflict | Leaves an existing destination unchanged and skips the current item.
| F12 | Use new name | Resolves the current conflict using Name; no existing entry is overwritten.
| Alt-X | Cancel job | Requests cancellation and waits for the owned worker; completed or partial effects can remain.
| Escape | Close Jobs | Cancels active work and closes this dialog. It does not detach a background queue.
| Alt-P, Alt-N | Results/target pages | Browse eight captured confirmation names or retained per-item outcomes at a time.
|===

A conflict has one current decision token and a 60-second decision deadline.
Expired, replaced and stale controls cannot act on a newer decision or dialog.
Skip, choose a new name or cancel are the available choices; replacement is not
performed. Permanent deletion always requires its distinct confirmation. The
confirmation displays captured filenames in pages, the source folder, and the
selected count including entries hidden by the filter. Paging or selecting a
preview row does not change the captured targets; F10 confirms that whole set.
After admission, the same list shows per-item outcomes. No deletion follows from an
unavailable trash area or from removing a desktop reference.

The worker opens anchored directories and revalidates observed source identity
before mutation. Copying preserves symbolic links as links, without recursively
following them; special files are refused. Regular-file mode permission bits and
modification time are preserved where supported. Ownership, ACLs, extended
attributes, birth time, sparse layout and hard-link topology are not promised.
Same-filesystem regular-file rename/move can publish with an exclusive hard link
then remove its source; cross-filesystem work and directory moves use bounded
copy/remove. These sequences are not an atomic transaction or rollback. A failed
copy never causes removal of its source. Source-removal or metadata failures can
leave a complete or incomplete destination and are reported as partial outcomes.
External writers can still change entries between identity checks and individual
filesystem calls; this is not an atomic compare-and-delete or a same-user sandbox. A partial fast move can leave both names
referring to the same file; editing either changes that shared file. Inspect
both names before retrying.

Each job admits at most 256 selected top-level entries and plans at most 4096
entries to depth 64. Copying uses 64 KiB chunks. Progress is coalesced to at most
ten updates per second; item, decision and final records retain their order.
A child final record is only provisional until Wait confirms its exit. Missing,
invalid or lost final results are reported as interrupted, with no automatic
replay of uncertain mutations. Cancellation is best effort, with a bounded grace
before process termination; a kernel-blocked call can still delay reap. The
browser remains responsive and renews its native leases while a job is active;
its ordinary five-minute idle exit does not stop a running job. Closing the
browser or losing its WM connection cancels and reaps the worker.

Trash implements the supported home-storage subset of the freedesktop Trash 1.0
contract. It uses absolute XDG_DATA_HOME/Trash, or HOME/.local/share/Trash when
XDG_DATA_HOME is absent or not absolute. The owned Trash, files and info
subdirectories must be private, non-symlink directories. Items on a different
filesystem are explicitly refused; no per-mount trash or deletion fallback is
created. Metadata records preserve original path bytes and deletion time. Restore
requires a valid matching record and available original parent, applies the same
conflict decisions, and reports incomplete cleanup honestly. Open trash may report
unavailable until a supported trash operation has created that area.

The current source folder refreshes after the mutation child reaps when it is
still displayed and no navigation intent is active. An unrelated newer navigation
is never superseded by this refresh. Retained results distinguish completed,
skipped, failed, cancelled, interrupted and partial outcomes; metadata/content
incompleteness and remaining source/destination objects are not called success.

== PORTABLE TARGET REQUESTS

A local target is an absolute filesystem path or a local file URI. An ordinary
absolute path is literal, including percent, question-mark and hash characters.
URI percent escapes are decoded exactly once and retain original filename bytes,
including non-UTF-8 bytes. Empty authority or localhost is supported; remote
hosts, user information, ports, opaque/relative URIs and raw query/fragment
syntax are refused. Encode filename question marks and hashes as %3F and %23.
Decoded paths must be absolute, contain no NUL and fit the 4096-byte path limit;
encoded target arguments are bounded before decoding. OS argument limits also
apply to a launch request.

Choose --dir, repeated --reveal, or repeated --properties. The forms are mutually
exclusive. --reveal loads the common parent and selects one to 256 requested
entries, bringing the first requested entry's page into view. It never executes
or opens the targets. A requested dot entry automatically enables hidden entries.
Duplicate targets, mixed lexical parents, root targets, dot path components and
missing entries fail as a whole; no partial selection is published. Repeated or
trailing separators are normalized for reveal/properties. Use --dir / to browse
the filesystem root. Symlinks and special files may be revealed and inspected;
their activation remains unavailable.

--properties selects one to 256 entries in their common parent and immediately
shows the observed single-entry properties or selection summary. Target resolution, including parent enumeration, runs in the
same isolated cancellable worker. The whole parent's admission limit still
applies. These are portable launch requests for separate browser instances,
not a single-instance daemon, FileManager1 service, new default folder handler
or general structured MFL files provider.

== OPTIONS

*--dir* _local-target_::
  Initial folder, default the user's home directory. Paths are at most 4096
  bytes. Folder ordering is directories first, then raw filename byte order.

*--view* list|grid::
  Initial native presentation. Default list. F7 switches it without changing
  item IDs, focus or selection. The choice is not persisted.

*--hidden*::
  Include dot entries. Default off; an explicitly revealed dot entry enables it.

*--watch* off|auto::
  Enable native directory invalidations plus 30-second reconciliation with auto;
  default off. F8 toggles this for the current instance. Failures use explicit
  manual fallback. See DIRECTORY WATCHING for consistency and lifetime limits.

*--reveal* _local-target_::
  Reveal an existing entry in its parent; repeat for bounded targets in one folder.

*--properties* _local-target_::
  Reveal one to 256 entries in a common parent; repeat the option to show their
  observed selection summary immediately.

*--socket* _path_::
  Explicit FvwmMFL Unix socket. Otherwise use FVWMMFL_SOCKET, then the normal
  FVWMMFL_SOCKET_PATH / XDG_RUNTIME_DIR / private temporary-directory discovery
  used by FvwmCommand. DISPLAY selects the endpoint. No network listener opens.

*--opener* _executable_::
  File-opening program; default xdg-open when found. Missing capability reports
  unavailable without executing a fallback shell. The absolute file path is
  passed as one argument.

*--terminal* _executable_::
  Terminal program; default x-terminal-emulator, then xterm when found.

*--action* _label=executable_::
  Add a configured selection-action button; repeat at most four times. The
  executable receives selected literal absolute paths as separate arguments.
  See CONFIGURED SELECTION ACTIONS for admission, validation and launch results.

*--inspect*::
  Run the same isolated scanner without X and emit one schema-version-1 JSON
  result. Path/name byte fields are standard padded base64 JSON strings. A loaded
  snapshot contains the root observation, hidden flag and stable item IDs with
  kind and metadata. Failure emits a failed result and exits nonzero. This is
  file metadata, not a protected-content or clipboard payload channel. It also
  accepts --reveal or --properties instead of --dir, emitting selected_ids in
  requested order on success. A missing target emits a failed result with no
  snapshot or selection. Invalid syntax/option combinations fail before work.

*--help*::
  Show command usage. Unknown options/extra operands fail.

== CONFIGURATION EXAMPLE

The executable installs with every build; adopting it remains optional. A working independent
consumer can be opened from a binding without replacing the default folder menu:

----
AddToMenu FileTools "Folder browser" Exec exec fvwm-file-browser
Key F9 A M Exec exec fvwm-file-browser
----

Explicit target examples (no target is executed by reveal/properties):

----
fvwm-file-browser --reveal /home/user/Documents/report.txt
fvwm-file-browser --properties file:///home/user/Documents/report%20draft.txt
fvwm-file-browser --inspect --reveal /home/user/Documents/report.txt
fvwm-file-browser --dir /home/user/Documents --watch auto
----

The browser uses a random per-process Form alias and existing Form defaults.
Personal FvwmForm defaults may set fonts/colors. It does not change theme or
core window policy. Run the executable directly in an FVWM session for an
initial folder whose name needs literal shell argument quoting.

== OWNERSHIP AND LIMITS

The collection package owns metadata/selection only. The file adapter owns raw
names, directory observations and actions. Reusable metadata policy does not
qualify clipboard payload lifetime or protection. Sensitive clipboard data must
not be routed through ordinary Form command expansion or MFL Echo broadcasts.

Native change markers use a separate bounded, coalescing mailbox from correlated
replies. The browser requests a fresh snapshot for its current Form and ignores
retired Form markers. Missing or invalid snapshots leave selection unavailable;
transport loss can end the session. A current-Form feedback transaction can renew
the existing idle deadline, while automatic publication and scale changes do not
count as user activity. Markers and their tokens provide freshness, not access
control or permission to perform file actions.

Native callbacks use Echo/MFL version 3 with an instance/frame identity, known
action and monotonically increasing native invocation ticket. The URL-base64
selection/focus packet prefixes its projection generation. The helper rejects
replayed tickets and stale native generations before resolving indices to IDs;
paths still use the encoded input field. These guards provide freshness, not
same-user or X11 authorization. The files provider below exposes admitted metadata and conditional view controls.

Initial configuration uploads use at most 32 commands per core acknowledgement.
Live updates use direct module messages, avoiding accumulated configuration
records, and wait for a native reply after each batch of at most 32 commands.
One reply slot and a ten-second total rendering deadline bound the handshake.
Live updates renew the existing five-minute native orphan timeout; the helper
still closes after its own five-minute idle limit.
Before commit, current native selection is reconciled through the owned earlier
projection, including entries newly filtered out. After commit, a native reply
establishes the published mapping. Explicit Select visible/Clear selection
controls use atomic selection overrides. Unknown, duplicate or over-budget
native state cannot become action data; recovery can recreate the view, and
missing/invalid publication or broken transport can terminate the consumer.
Typed action providers and complete owner/install/platform acceptance remain with
FILE-VIEW/DATA/ACTION-01.

The separate observer has a 16 KiB private request and 128-byte response-frame
limit. Its records carry constant invalidation/lifetime states, never paths,
event names or file content. One observer event channel and one desired folder
bound pending work; superseded observer results cannot own a new directory.
`FVWM_FILES_WATCH instance state` Echo observations report only off, starting,
native or manual state after native publication. They are ordinary metadata,
not a protected-content channel.

No preferences or directory history are written to disk. Raw metadata remains
in the helper's ordinary Go memory; no secret-storage claim is made. Results and
queues have finite limits, including a 4 MiB private worker envelope and sixteen
native callback slots. Slow/broken MFL output closes the session according to
its existing bounded transport policy. Native GUI and external application
accessibility/interoperability need their own acceptance.

== FILES PROVIDER

While connected, each browser registers an independent instance with FvwmMFL.
`FvwmCommand --request` can discover instances and query `state`, paged `items`,
paged `selection` and observed typed `properties`; see FvwmMFL(1) for schemas,
base64 path/name bytes, decimal-string sizes/timestamps and paging generations.
The current native selection is captured without requiring a button callback,
including selection made since the last browser action. Queries preserve the
native windows, input drafts and the helper's existing idle limit.
State also exposes typed `progress` (`state`, `known`, `completed`, nullable
`total`) and fixed `availability` metadata (`ready`, `open_visible`, `properties`,
`terminal`, `custom`, `cancel`). `availability_generation` is the current state
query generation. Unknown totals are null, not invented percentages. Availability
counts follow the current filter/selection; executable configuration, worker
intent and readiness transitions also invalidate the generation. Readiness is
advisory observed metadata and does not replace action admission or worker
identity validation.

An explicit state query also returns read-only `bindings` diagnostics: `intent`
and `projection` contain the fixed source/identity-byte counts, current state,
one-in-flight/one-pending flags and invalidated/started/published/rejected counters.
`watch_timer_active` reports whether the browser loop currently owns its watch
sampler. Reading this metadata does not trigger binding work or change counters.
It creates no polling service or UI control. Stable counters between explicit
queries can show that no unsolicited binding work ran; they do not measure
kernel wakeups or replace the observer/idle timer limits described above.

Writable clients may also apply generation-checked selection edits, literal
filtering, observed sort, list/grid presentation and observed-properties controls.
Query the current state first and use the latest returned generation for each
edit. Selection edits replace/add/remove up to eight stable IDs or clear the
complete set, with the existing total cap of 256. Unknown IDs, malformed values
and stale state refuse the whole requested edit. See FvwmMFL(1) for exact schemas.

These controls use the existing native publication handshake. Success means the
native view was published; interrupted client waits do not undo submitted work.
Selection/filter/sort/properties and list/grid updates retain native windows
and input drafts. Accepted controls renew the idle limit.
Properties use admitted observations, with no recursive scan or link following.
If the actual window is too small for a requested view, the correlated control
returns `operation_refused` and retains the current mode and usable browser.
Enlarge the window and submit a fresh view request. Requesting the already
current mode succeeds without changing the native generation.

Queries read only the admitted snapshot. Writable clients can also submit typed
Home/Up/Back/item/path navigation, refresh, open, terminal and configured-selection
actions. The browser captures current native selection and checks the generation
before admission. Slow work stays in its existing isolated worker. A client can
choose a configured action index, but cannot provide an executable or shell text.
Live `reveal`/`inspect` requests accept up to eight canonical base64 absolute
target paths in one parent and use the same worker to resolve the whole set.
Success replaces selection, clears the admitted filter and focuses/scrolls to
the first requested item; inspect also shows observed properties. Same-folder
handoffs preserve native windows and drafts. Missing/mixed-parent/duplicate
requests cannot publish partial targets; no target is opened. Explicit hidden
targets enable hidden entries. A draft filter can be applied again explicitly.
Typed `hidden` rescans with an explicit flag; typed `watch` configures/retries
the existing observer. State exposes configured action index/labels and
opener/terminal availability, without executable details.
Canonical base64 absolute paths retain bytes, with a 192-byte per-path bound;
longer paths use native path entry. See FvwmMFL(1) for exact values schemas.

The native-acknowledged reply contains the latest accepted `work` ID/operation/
status. Query state for its loaded/started/failed/cancelled/superseded outcome.
Only the latest accepted worker outcome is retained in memory. Started means
process handoff, not application completion. Cancel by work ID; cancellation
keeps the worker slot until reap, suppresses late directory publication and cannot
undo a process handoff. Native navigation can supersede external work. IPC wait
cancellation only discards the wait. No file content is exposed. Metadata and selection/focus changes invalidate
page tokens. Discovery is limited to eight producers, with one active query per
producer; a busy/unavailable instance yields an explicit error. Loss of the
provider connection closes its binding/view lifetime. Start a fresh browser to
register a new provider and obtain a full snapshot; old tickets and uncertain
application handoffs are never replayed. Old browser/MFL
combinations cannot register: build and update these shipped consumers together.
The `jobs` state field reports the latest admitted job: ID/generation, operation,
active/state/sequence, pending decision, item count and known/unknown progress.
A finished record does not clear active until the child has actually reaped.
The native dialog owns mutation submission; ordinary file-provider action
requests do not implicitly become destructive jobs. Clipboard payload
ownership/protection and FileManager1 remain separate work. No SQLite dependency
is introduced.

== PORTABLE FOLDER HANDOFF

A single optional positional local folder is equivalent to --dir and accepts
the same absolute local path/file URI grammar. With no target, use Home.
It cannot be combined with --dir/--reveal/--properties or another argument.
An unsupported URI scheme is refused without fetching or opening it.

--reuse is opt-in. Discover at most eight providers and choose an idle,
capability-compatible instance already observing the same lexical folder.
For a folder launch, refresh it; for reveal/properties, submit the complete
bounded target set. No item is executed. Existing standalone launches retain
independent windows. No matching idle/capable provider, or a target set above
the IPC bounds (eight paths, 192 decoded bytes each, 384 total values bytes),
uses the existing independent launch path. Larger requests keep its 256-target/
4096-byte limits. Matching does not resolve parent aliases or symlinks.

Reuse accepts only folder/target/socket options. Explicit view, hidden, watch,
program/action or --inspect options are refused with --reuse; configure those
on an independent browser first. An older browser missing required capabilities
is skipped without sending it a new unsupported action.

A successful reuse prints one JSON admission receipt with version, provider and
work ID/operation/status, then exits. Accepted does not mean loaded or application
completion; query the matching work in FvwmMFL(1). The browser's normal worker
lifetime and error presentation continue independently of this client.
The client has a ten-second total IPC deadline, within which each correlated
request has its ordinary six-second terminal-reply allowance. Query/current
precondition refusal can retry once. A submitted request with lost/malformed
reply returns an unknown-outcome error and never starts a duplicate view.

After admission, the explicit present control de-iconifies, focuses and raises
only that browser through the shared FVWM command engine. Focus uses the normal
core viewport/desk policy and does not warp the pointer. Presentation is separate
from worker completion; a presentation failure returns an error while admitted
work may continue. Sensitive clipboard content is not a request payload.

Installation also provides fvwm-file-browser.desktop under the
application data directory. It advertises only inode/directory, uses TryExec and
one literal URL field in `fvwm-file-browser --reuse -- %u`, and also launches Home
when invoked without a URL. No shell expands the URI. It adds no D-Bus activation
or startup-notification guarantee and never changes the user's MIME defaults.
The entry remains marked development; ordinary Open/Save dialogs, automatic
FileManager1 ownership and full default-provider adoption remain separate.

Examples:

....
fvwm-file-browser --reuse 'file:///home/user/Work%20files'
fvwm-file-browser --reuse --reveal '/home/user/Work files/report.txt'
fvwm-file-browser --reuse --properties '/home/user/Work files/report.txt'
....

== EXIT STATUS

Zero means the consumer closed normally or inspection loaded. Nonzero means
invalid arguments, unavailable MFL connection, inspection/worker failure or
transport failure. A failed UI action is shown in the browser and can be retried
after refresh; it does not necessarily terminate the consumer.
