== NAME

fvwm-session - portable FVWM login owner and optional session services

== SYNOPSIS

*fvwm-session* [*--no-autostart*] [*--* _fvwm3-arguments_...]

== DESCRIPTION

The packaged FVWM desktop entry starts this login parent. It establishes the
session environment, starts the installed *fvwm3*, and runs eligible XDG
autostart applications once after the core acknowledges initial startup.
It uses the existing Go runtime and requires no session bus or desktop toolkit.
Optional D-Bus power and outbound-notification integration is disabled by
default; portable power discovery and fixed manual-lock coordination remain
available without it.
The native *FvwmDesktop* Session panel observes the owner and coordinates
cooperative application logout through the core. Complete service integration
and release qualification remain separate work.

Direct *fvwm3* invocation remains available and starts no new autostart owner.
Existing configuration files, startup functions and custom *-f* arguments remain
usable. For example, from an X startup script whose existing display and
authentication environment are already configured:

----
exec fvwm-session -- -f "$HOME/.fvwm/config"
----

Use *--no-autostart* when configuration startup functions or an external tool
already launch the applications. The separator *--* passes all following
arguments literally to FVWM. Labels, desktop-entry fields and wrapper arguments
are never evaluated as shell programs by this wrapper. Explicit FVWM display
options select the same display for ownership, acquisition and applications;
the last applicable display option wins. Option-looking values belonging to
other FVWM arguments retain their literal meaning. Unknown, incomplete or
information-only core invocations use direct FVWM execution without autostart
rather than inferring an ownership display.

== ENVIRONMENT AND OWNERSHIP

Missing *XDG_CURRENT_DESKTOP* becomes *FVWM3:FVWM*, and missing
*XDG_SESSION_TYPE* becomes *x11*. Existing values, *DISPLAY*, *XAUTHORITY*,
*HOME*, *PATH* and *XDG_RUNTIME_DIR* are preserved. The default bus policy also
preserves the inherited bus environment and starts no session-bus adapter. The wrapper
does not invent a runtime-directory environment variable.

A nonempty *SESSION_MANAGER* selects the existing externally managed XSMP path:
the wrapper directly executes FVWM and skips its own lifecycle/autostart owner.
The external session manager retains its existing restart and shutdown policy.
This does not prove that an inherited external manager is reachable.

For an owned login, a private nonblocking record lock distinguishes concurrent
wrappers on the selected display. Local numeric *:D* and *:D.0* share one lock
key; another screen stays distinct. The actual display argument and environment
remain unchanged. Arbitrary host/transport aliases are not a promised common
session identity. A competing WM must still acquire the X display before startup
can be acknowledged.

The record uses an owned private runtime directory or cache leaf. Its inode is
persistent: no lock-file removal, PID-file signaling or adoption occurs.
Unavailable or busy ownership reports direct-FVWM fallback without autostart.
The parent passes the same locked file description to the core. A surviving
native core retains it after parent loss and through native same-PID Restart.
Closing one holder does not unlock the survivor. Ordinary executed applications,
modules and an explicit replacement program do not inherit this lease.
Do not set the private readiness/lease descriptor environment yourself.

The parent owns the directly started WM, temporary acquisition/adapter workers
and a session bus only when the explicit startup policy creates one. A normal
FVWM Restart replaces the same WM process and does not repeat autostart or bus
bootstrap. No automatic WM restart or application retry is performed.
Autostart applications are independent launches, not adopted session services.
The parent does not terminate them or borrowed services.

== OPTIONAL SERVICES AND SETTINGS

The shared *$FVWM_USERDIR/desktop-state.json* preference file supplies four
settings in *group:session*. The default user directory is *$HOME/.fvwm*.
Use *FvwmDesktop* Session settings to change them; there is no second session
preference store.

* *session_bus*: *off* (default), *reuse* or *start*. This takes effect at the
  next owned login. Changing a preference cannot change bus addresses already
  inherited by running applications.
* *session_notifications*: *off* (default) or *external*. This enables a finite
  outbound client for an existing notification server after a live owner
  handshake. It does not start a notification server.
* *notification_dnd*: boolean, default *false*. Do not disturb suppresses
  outbound notices quietly. It applies after the live handshake.
* *session_power*: *portable* (default) or *login1*. It applies after the live
  owner handshake; changing provider invalidates old capabilities until an
  explicit power probe. It does not change the session-bus policy.

With *session_bus=off*, login starts no session-bus helper and preserves the
inherited address. Portable power discovery does not require a bus. *reuse* authenticates
an explicitly inherited usable session address; an absent or failed service leaves the portable desktop available. *start*
first reuses a working inherited bus. Otherwise, if the optional adapter is
available, it starts an installed *dbus-daemon* in the foreground and confirms
its address and handshake before launching FVWM or autostart applications.
Only absolute *PATH* components are searched for the fixed daemon name.
There is no package installation, system-bus startup or implicit bus autolaunch.

The optional native adapter has independent session-notification and existing
system-bus power branches. The notification branch accepts one explicit Unix
session-bus address. Build with *-Dsession-dbus=enabled* and libdbus-1 >=1.14;
default builds install an unavailable stub without linking that library. The startup budget is five
seconds; each isolated notification adapter call has a two-second deadline,
and power acquisition/calls have a four-second parent deadline. Output is
capped at 16 KiB with finite message limits. Each D-Bus method call has a
one-second timeout. A new daemon address is limited to 4096 bytes. Missing or disabled support reports unavailable and
preserves login. Full platform/service qualification remains separate; see
*INSTALL.md* in the source distribution. A compiled adapter reporting available
does not establish a connected bus; readiness requires the actual handshake.

Refresh/reprobe acts on the existing environment and address. A failed bus is
not replaced after applications start. Status distinguishes owned, borrowed and
independent records, with starting, ready, unavailable, failed and stopped
outcomes. A process start is not proof of service or application readiness.

The parent tracks at most 32 notification IDs for its actual bus and server
owner. It sends plain UTF-8 summaries up to 160 bytes and bodies up to 1024
bytes, with control characters refused. Close requests apply only to its own
IDs and the same server owner. Server replacement invalidates those IDs.
Unavailable notifications use a local native notice where the desktop action
provides one. No notification history, server, tray or bundled authentication
locker is added.
Power failures do not erase these IDs, and session-notification loss does not
disable independent portable/system power providers.

== POWER AND MANUAL LOCK

The default portable provider resolves fixed native commands through conservative
absolute PATH roots. Linux prefers installed systemctl, otherwise shutdown;
FreeBSD and OpenBSD use shutdown. Installed means request-capable with unknown
authorization; discovery never executes a power request to test permission.
No arbitrary provider, executable path or argument registry is accepted.

The optional login1 provider connects only to an existing local system bus,
using an explicit inherited local address or the conventional existing socket.
It never starts a system bus or activates login1. Bus GetId/GetNameOwner
identify the bus and unique service owner. The fixed login1 Manager supplies
CanPowerOff, CanReboot and CanSuspend observations.
PowerOff/Reboot recheck permission and pinned bus/unique-owner identity, and
send interactive=false only for yes. No, challenge, na, inhibited,
inhibitor-blocked, challenge-inhibitor-blocked and unknown do not authorize a
request. Authentication and inhibitor management are outside this provider.
The compiled-disabled helper reports unavailable without libdbus linkage.

Session and its menus report per-action capability and bounded request outcomes.
A request acknowledgment is not completed shutdown. After a denied, timed-out,
disconnected or uncertain request, no fallback or automatic replay is attempted.
Refresh and explicitly probe before deciding whether to request again. The
existing direct FVWM/external-session native fallback remains usable. Power
and notification providers have independent failure state.

Manual Lock starts only an installed xlock or slock. The parent retains exactly
one observed child across FvwmDesktop/controller and ordinary FVWM Restart and
refuses duplicate admission while pending/running. Once Start succeeds, requester
disconnect, request deadline, controller restart and WM exit do not terminate the
locker. Its waiter records exit; started, running and exited never attest screen
protection. This is manual-lock process coordination, not a secure-readiness
implementation.

Coordinated suspend is explicitly unavailable. The parent refuses it before
constructing a native power request or sending a Suspend method, regardless of
backend capability or a running locker. This slice has no qualified positive
secure-lock witness, authentication implementation or inhibitor coordination.
See *FvwmDesktop*(1) for controls and *FvwmMFL*(1) for the typed public operations.
Full service, platform, physical-lock and release acceptance remain separate.

== PRIVATE OWNER CONTROL

The parent precedes and survives the desktop module. A private Unix socket
and random capability, inherited by its children, expose only finite lifecycle
verbs. The endpoint uses an owned private directory and socket; cleanup preserves
a replaced inode. Same-user processes are trusted peers, not a confidentiality
boundary. Portable Unix path limits can make an unusually long endpoint path
unavailable without preventing login.

This internal channel admits eight connections/queued requests, one active
mutation, 16 KiB frames/status and five-second request deadlines. Disconnect
cancels a request, not the desktop or an already started locker. Session
generation and current-operation tokens reject stale mutation controls. Private
messages use version 2, and power mutations require a separate current provider-generation token. The
optional native client retains JSON version 1 with kind power; public Session
queries use schema 2. These are separate internal/public contracts. Session
generation belongs to the parent lifetime; it is not a detector for each
same-process FVWM exec.
The channel accepts no arbitrary commands, argument arrays, executable paths
or window IDs. Public clients use the existing *FvwmMFL* typed session/settings
and operation interfaces; they should not construct this private protocol.

== STARTUP ACKNOWLEDGMENT

An inherited private pipe carries one acknowledgment after the core completes
initial capture, startup functions and state loading. A current parent also
requires positive acknowledgment that the core retained its shared owner lease.
A mismatched older core cannot acknowledge that handoff, so autostart is disabled
while the WM remains usable. Lease acknowledgment still runs with
*--no-autostart*. A failed pipe setup disables acquisition without preventing the
WM launch; it does not establish an acknowledged handoff.

The core promptly removes private descriptor environment and keeps the lease
close-on-exec during ordinary work. Only native Restart temporarily preserves it
across the core's own exec. The readiness pipe uses one nonblocking, SIGPIPE-safe
write and closes once. This acknowledges core startup and lease retention only,
not completed asynchronous modules, painted windows, application readiness or
locker protection. After fifteen seconds, EOF or malformed acknowledgment,
autostart is unavailable for that login and a diagnostic explains why. The WM
remains usable; no fixed sleep substitutes for readiness, and later Restart does
not replay autostart.

== XDG AUTOSTART

The parent runs one isolated acquisition worker after acknowledgment. It reads
*autostart* directories under the XDG configuration roots, using the existing
Desktop Entry parser and literal *Exec* expansion. Entries run in stable filename
order. The user configuration directory takes precedence over system directories
by filename before parsing or filtering. A hidden, malformed or unavailable
winning entry never exposes a lower-priority copy.

*Hidden=true* disables an entry. *OnlyShowIn*, *NotShowIn* and *TryExec* control
eligibility; both desktop-filter keys together are invalid, including empty
values. *TryExec* must be an absolute executable path or a bare executable name.
*NoDisplay* is menu visibility and does not disable autostart.

*Terminal=true* is unavailable in this portable slice; the wrapper does not launch
it outside a terminal. *DBusActivatable=true* uses a valid literal *Exec* fallback;
without one it is unavailable. No D-Bus activation is attempted. A nonempty
*Path* must name an absolute directory. No removable-media autorun is processed.
Bare executable names in both *TryExec* and *Exec* search only absolute *PATH*
components; empty and relative components are ignored. Acquisition pins the
observed executable to an absolute path. Files and directories can still change
before launch; this observation is not an immutable executable identity.
A launch result means started, not ready; exits, failed launches and skipped
entries have distinct diagnostics. Per-application errors do not block login.

The scan admits at most sixteen configuration roots, 1024 observed directory
entries per root, 256 winning desktop entries, 256 KiB per file and 8 MiB total
input. The private worker reply is limited to 512 KiB and acquisition to five
seconds. Global overflow refuses the scan as a whole before any application
starts. Diagnostics and retained child records are bounded. One blocked filesystem
operation cannot be interrupted by a context check; the isolated worker supplies
the acquisition deadline. Other private path and process system calls can still
block in the kernel.

For a user-controlled optional terminal, create
*$HOME/.config/autostart/local-terminal.desktop* with:

----
[Desktop Entry]
Type=Application
Name=Optional local terminal
TryExec=xterm
Exec=xterm
OnlyShowIn=FVWM3;FVWM;
# Keep disabled until this user explicitly chooses to enable it.
Hidden=true
----

Change *Hidden* to *false* only when this entry should run at the next owned
login. An installed optional program is not automatically added to this list.
Do not launch the same application again in a configuration startup function.

== SHUTDOWN AND ERRORS

An explicit shutdown signal goes only to the directly owned WM. The first
signal cancels further acquisition/helper work and starts a fixed five-second
cooperative grace period. Repeated signals do not restart that period or
broadcast to a process group. If the direct WM has not exited at expiry, the
parent requests termination of that same owned process and observes its actual
Wait result for up to one further second. It returns the observed exit status;
if exit is still unconfirmed, it returns failure and a reserved diagnostic says
so. The grace/reap phase is not a bound on all later cleanup. Outstanding
autostart acquisition gets a two-second final cancellation barrier; its direct
worker termination observes actual Wait for up to one second. An unconfirmed
worker exit is reported. Adapter cleanup has its own bound, and one
kernel-blocked Start, termination request or I/O operation is not preemptible.

This signal path does not close independent applications or admitted lockers.
The native Session panel's Log out action first asks the core to close eligible
managed applications cooperatively. Cancel or its deadline stops further
requests; an already sent close can finish and closed applications cannot be
restored. A guarded final request rechecks that no eligible application remains.
See *FvwmDesktop*(1) for the scope and external XSMP handoff. Ordinary direct FVWM
Quit remains available and does not prove application work has been saved.

Confirmed WM exit completes this parent's session and stops/reaps an owned bus.
Owned-daemon cleanup requests TERM, waits up to two seconds, then requests KILL
for that same owned child and waits up to one further second. A delayed kernel
exit remains a reaping limitation. If WM termination remains unconfirmed, the
parent leaves the owned bus running for the possibly live session. Borrowed
daemons, independent applications and admitted lockers are never signalled by
this cleanup.

A failed ownership/startup path has an explicit diagnostic. Parent-crash cleanup
of an owned optional bus and complete service-provider coverage remain separate
work: no guardian, automatic adoption or orphan-free bus recovery is promised.
The inherited native-core lease prevents another matching wrapper from claiming
that still-running core's session; the unavailable parent control endpoint is
not silently replaced.

The WM's exit determines normal session completion. Invalid command options,
missing required executable and owner failures are reported on standard error.
A refused autostart scan leaves the WM running. No automatic package installation,
privilege escalation or lock-provider readiness is implied.

== FILES

*$XDG_CONFIG_HOME/autostart*::
User Desktop Entry files with the _.desktop_ suffix; *$HOME/.config* is the default configuration root.

*$XDG_CONFIG_DIRS/autostart*::
System Desktop Entry files with the _.desktop_ suffix in root order; */etc/xdg* is the default configuration root.

*$FVWM_USERDIR/desktop-state.json*::
Shared desktop preferences: fifteen registered keys plus retained wallpaper,
including the four session settings. Supported old schemas load automatically;
a successful save writes schema 6. The compact Session editor has four fields;
the appearance edit-all form retains eleven.
